# T4：固定预算的实际事件读取

## 问题与假设

指定因果时序模块能否比相同输入的逐时刻普通头更可靠地读取实际顺序、进度和错误？实例区域和帧间变化是否有用？本轮允许不支持这些假设，评价后不追加训练。

## 方法与对照

预注册为20组原创坐标轨迹，10训练／5开发／5测试，每组6种过程，共120段视频。所有副本和决定前缀随轨迹组划分；原probe仅进入训练。五类基础结构均在训练出现。单一渲染器、无手部、每段8个实际观察，评价4—8帧前缀。测试30段、150个决定、330个实例状态、5个同终态换序对；不是正式未见汉字／字体测试。

固定完整Show-o2，新增312张图编码610.96秒，复用105张，共417×729×1536。UMM更新0。A+B共同训练一次：8epochs按patience3停止，开发最优第5轮；训练实例匹配100%，开发7/11。T3遗漏的A质量置信度loss已补齐，实际首次梯度非零，未回改旧成绩。

七个时序／普通头各固定12epochs、456次更新、3600次决定样本暴露，seed42；各自只按dev loss选检查点，之后统一读取测试结果。C为1107981参数，普通头1104653，输入投影和可匹配输出层共用初始化。B3保留与B4相同的当前、相邻差分、参考差和时间标量，仅取消跨时刻访问；它仍有相邻变化信息。B1额外去掉相邻差分与时间，连B当前墨迹分支也只给当前输入，20组终态配对的输入全部相同。

主系统实例查询含规范ID、类型和模板导出的粗中心提示；没有精确mask或实际事件日志。oracle以正确区域同时训练和评价独立的匹配头。无变化分支清除全部相邻差分输入；整图池化和无进度监督按配置执行。时间打乱在每个已观察前缀内保留空白首帧／当前末帧，重算原像素差和特征差，不使用未来帧。

## 失败、解释与下一步决策

- B4的“三”换序在后段三次读成规范顺序；同终态对失败。oracle状态100%仍把正常／反向／提前换笔的部分三笔历史排序错误，说明定位之外还存在多事件历史读取问题。
- B4把“三”的合并事件中4个前缀当成可观察，先输出[0]。不能根据整体顺序95.33%忽略这种错误接受。
- 无进度监督的进度MAE大幅恶化，但方向／动作更好；当前结果不支持进度辅助任务提高其他任务。多任务干扰与dev选择差异只是待验证解释，未追加训练验证。
- 打乱内部帧未明显降低严格顺序，配对反而5/5；不能据此宣布模型掌握了真实时间依赖。累积墨迹的嵌套状态本身可重建部分顺序，且B3已有相邻差分，当前数据不足以证明时序Transformer的必要性。

因此：支持实例区域与变化信息在本批有用；尚无证据证明指定C全面优于匹配普通头。定位、三笔历史、未知接受、进度一致性仍未稳定。保持全部原始预测、失败与权重，不追加seed／轮数／LoRA，提交T5决策。
