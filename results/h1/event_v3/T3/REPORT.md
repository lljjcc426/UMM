# T3：指定模块的小集拟合

问题：A—C是否能在固定小训练集读取真实事件，D能否按状态给出正确动作？

假设：先定位笔画、读变化、再组织时间，有望拟合D0；跨结构的定位可能成为独立瓶颈。

方法：复用T2的30段视频，三、十、竖平行、折共24段用于小集拟合，斜交叉6段用于开发诊断。各决定时刻只可看过去，C为2层256维4头因果Transformer。UMM全部冻结，CPU fp32小模块、seed42、AdamW1e-3／wd.01、有效batch8、最多12epochs、dev patience3；运行前协议见preregistration.json。

对照：正确实例区域单独做固定C的输入替换诊断；未来帧扰动验证因果性；六类预期动作／首错由案例设计独立列出，与D的真状态输出核对。

结果：

|---|---:|---:|

A+B为2122469参数，12epochs（开发最优第9轮）；C为1107981参数，5epochs后按patience停止。没有追加轮数。固定C把开发实例区域替换为正确区域后，状态85%、最终顺序5/6、动作60%、进度MAE0.0893；这是交叉输入诊断，非公平训练的oracle上界。

接口为[1,8,3,196]，mask为[1,3,729]；各状态张量和有限loss见interface.json。改变第6—8帧后，前5帧全部输出差异为0，支持当前实现满足因果限制。30个案例的独立终态预期动作／首错核对30/30；仅覆盖本批六种受控过程，不替代全部规则图验收。

失败：开发斜笔类型在这次训练里完全未出现，类型embedding未训练，A掩码全部失败。因此不能把开发下降单独归给UMM特征或时序架构。给正确区域后仍有残余状态／动作错误。代码审阅还发现A的confidence投影没有加入loss，输出未校准且未用于mask／C决策；其数值不能作可靠匹配置信度。本次权重与结果保留，T4共用空间模块须补齐质量监督，提前登记，不回改本次成绩。

解释：小训练集达到事先固定的mask／变化／状态／最终顺序拟合条件，可以开展一次有控制的T4。尚未证明新结构泛化，状态分数高也没有保证动作准确。开发oracle替换的改善集中指向实例绑定，符合失败分支C；类型未见又属于明确的域划分因素。

下一步：T4让所有基础类型在训练出现，独立生成训练／开发／测试几何，保持同底层轨迹的所有视频在同组；比较B0、B1、同输入无时序头B3、B4、匹配oracle、时间打乱及预算内消融。不开UMM LoRA，不把这些小头称为统一训练改善。原130视觉测试及全部旧权重保持。
