# 目标空间头的完整批次拟合诊断

2026-10-17完成。**同一目标空间头可以拟合已见目标题，但开发定位仍只有13/28。** 本轮把误差进一步收敛到目标掩码的泛化与边界读取，仍未通过H1前置门槛。

## 为什么追加这一轮

[首轮空间头](../target_grid_v1/README.md)的训练定位30/84、开发7/28，训练损失波动。为检查这个读出方式是否有能力拟合已见目标，复用同一视觉／问题缓存、监督、头结构及初始化，采用完整84目标批次、学习率0.0003、1000次更新。其余AdamW设置、种子10420和0.5阈值保持。训练前固定设置见[plan.json](plan.json)。

头仍有98,369个参数，完整UMM及原状态适配器全部冻结。训练36个几何组／84个目标，开发12组／28个目标。优化预算、学习率和批次同时改变，不能将差异归于某个单一因素；开发数据已被查看，本轮是后续开发诊断，不是新的独立验证。

## 结果

| 条件 | 训练定位命中 | 开发定位命中 | 开发目标IoU／F1 |
|---|---:|---:|---:|
| 实际目标问题 | 82/84 | 13/28 | 62.0%／75.0% |
| 同图换成另一目标问题 | 0/84 | 0/28 | 10.8%／18.1% |
| 对所有目标使用全部笔迹 | 20/84 | 6/28 | 40.2%／56.2% |

命中仍要求四个边界都在12像素误差内，使用预先固定的最大四连通部分及网格中心换算。实际问题的开发命中率46.4%，12组bootstrap区间[25.9%,65.5%]。相对换问题改善46.4个百分点，配对区间[25.9,65.5]；相对全部笔迹改善25.0个百分点，区间[7.4,44.8]。

训练目标IoU98.5%、F1 99.2%，说明这一新增空间头在本批已见题上能够使用UMM问题表示区分目标。开发目标IoU与定位均明显低于训练，仍不满足可靠定位要求。不能把头的成绩当作原语言模块已会生成正确坐标，也不能代表未见汉字或字体。

## 掩码与边界错误

训练未命中的2个目标均为邻近横线，目标IoU仍为90.3%、93.3%，边界因少量额外格偏离。开发15个定位失败中，既有漏掉端点，也有额外格、交叉处断裂及其他位置的误报。固定示例：`cross-0-竖线`的目标IoU88.9%，最大连通部分仍在中途结束，边界未覆盖完整竖线。

复用相同预测做事后诊断，不改变模型或0.5阈值：

| 边界来源 | 训练命中 | 开发命中 |
|---|---:|---:|
| 预设最大连通部分 | 82/84 | 13/28 |
| 所有预测前景格的外接范围 | 73/84 | 3/28 |
| 正确目标网格，标注上界 | 84/84 | 28/28 |

开发中，合并全部预测格只修复2个最大连通部分失败，却破坏12个原本正确的定位。直接扩大范围不能解决问题；既要减少误报，也要保留同一目标的连续部分。正确网格的28/28只验证当前数据下网格分辨率与坐标换算足以满足此阈值，属于使用标签的确定性上界，不是模型成绩。逐例证据见[边界诊断](decoder_diagnosis.json)。

## 后续与范围
