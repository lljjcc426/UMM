# 参考目标的直接坐标输出诊断

2026-10-17，本机完整Show-o2-1.5B-w-video-und UMM，使用上一轮加框状态适配器。**当前权重不能直接提供可用的目标坐标；尚不能据此区分空间定位不足与坐标输出任务不熟悉。**

只输入完整参考与目标名称，输出`{"box":[x_min,y_min,x_max,y_max]}`。使用12个新开发几何组、28个目标，覆盖三横、两竖、交叉；下半部空白，没有当前进度或答案提示。只用一种问题表达、一份最终权重，不搜索提示、不训练、不使用原视觉测试。构建前固定的设计见[plan.json](../../../../data/h1/reference_localization_v1/plan.json)。

| 指标 | 结果 |
|---|---:|
| 四个坐标均在12像素误差内 | 0/28 |
| 左右或上下边界颠倒 | 4/28 |
| 坐标平均绝对误差 | 128.28像素 |
| 推理及图像准备，不含载入 | 120.7秒 |

固定JSON标点和整数范围保证了28份输出都可解析，不保证空间正确。解码在全部合法整数上逐token选择，不读真值、不提供正确框候选，也不强制边界间的大小关系。0/28在12组bootstrap下区间为[0,0]，只表示本批全部失败，不表示一般化的确定结论。

9个目标输出相同的`[312,31,312,31]`，4个输出`[216,210,51,50]`，存在明显的固定坐标回答。完整坐标误差、问题和原始答案均保留在`score.json`及`predictions.jsonl`。

上一轮状态适配只监督“有／无”“部分／完整”等答案，未监督坐标。此处还改变了输入为参考单独展示，因此负结果只说明当前权重与此接口的组合不可直接用于定位。没有运行预测框下的状态推理：全部位置未达到预设几何标准，先修正定位接口更有信息价值。不能用此结果推断UMM经过位置监督后仍无法定位。

下一步固定坐标表达并加入参考位置监督，先检查训练内是否学会，再用新的开发几何检验迁移；同时保留原状态题和缺少参考题，防止能力退化。随后比较正确位置、预测位置和无位置下的状态判断。定位阶段只读取完整参考与目标名称，不读取当前状态。两项门槛尚未通过，顺序学习、H2与H3未开始。

新增`scripts/h1_reference_localization.py`、12张参考图、案例与设计，以及本目录输入、逐题预测和评分。修改研究进度、实验计划及门槛协议以记录负结果和下一步。未修改旧模型权重、训练数据或历史评分，没有删除文件。实际28目标运行验证了接口，另目视检查一张交叉参考图；仓库检查仅验证文件与链接。
