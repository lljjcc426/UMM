# 研究进展

## 当前阶段：H1首轮诊断已运行，继续定位理解瓶颈

工作标题：**实际笔顺理解驱动的统一多模态中文书写视频生成**。

当前主线为方案四＋方案二：联合训练过程理解与生成，生成时观察实际结果再续写。首阶段采用单字、固定视角、无手部遮挡、清楚笔画及保留基本结构的风格变化。

工作分支：`research/stroke-order-joint-feedback`。后续本主线的数据、实验和文献更新集中在该分支，待办与阶段结果通过[总跟踪Issue #1](https://github.com/lljjcc426/UMM/issues/1)跟进。六个方案的分工及研究范围见[主线定义](MAINLINE.md)。

## 已有工作

- 已梳理笔顺生成的任务定义、直接前作、可检验机制、数据方案、对照与指标。
- 对VidScribe中8段公开生成样例进行了定性核查，记录了笔顺、方向、文字增生及多字结构等问题，也保留了较好的生成结果。样例数量不足以估计模型总体错误率。

- [结论依据](DECISIONS.md)记录了指标解释和研究范围的修订。
- [H1模型诊断](../experiments/h1_diagnostic.md)已运行：Qwen3-VL-2B 4-bit，Apple M5/16GB，33个首轮输入＋30个单项补充＋6个基础问答，无训练。模型能完成简单线条计数和自然语言半笔续写判断，结构化过程任务仍不可靠。

## 最近结果：2026-10-16

首轮12个全部过程帧输入中，实际顺序1/12、完成状态0/12、动作与目标0/12；两组同终态换序对均未通过。31个可解析回答全部遗漏目标字段，另外2个回答截断。准确文字状态下仍有规则判断错误，因此不能把失败全部归于视觉理解。

补充单项提问后，实例、完成状态和实际顺序仍未可靠恢复；基础问答能正确回答空白/单横/三横计数及“半条上横应继续”。下一步先澄清实例绑定、提示与状态接口对结果的影响。完整分母、配对限制、原文及配置见[诊断报告](../experiments/h1_diagnostic.md)。这些小样本结果不代表其他模型或真实书写视频能力。

## 实验顺序

1. H1／SO-01：实际笔顺、首错及当前笔完成程度的理解诊断。
2. H2／SO-02、SO-02B：先诊断正确控制的执行，再验证联合训练与实际反馈是否改善自由生成。
3. H3／SO-03：相同数据、输入与可比预算下的联合、分离和专门模型对照。
4. SO-04：多字与风格泛化。
5. EF-01：过程信息在少步生成和缓存压缩中的保持。
