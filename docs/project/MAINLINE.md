# 实际笔顺理解驱动的统一多模态中文书写视频生成

这是探索阶段的工作标题。当前主线于2026-10-16确定，方法、底座和效果仍需实验确认。

> 通过联合训练，让UMM学会理解中文视频中实际发生的笔画顺序，并利用这种理解，边观察、边生成后续书写过程。

本主线集中在 `research/stroke-order-joint-feedback` 分支持续推进；文献筛选、数据、实验和结果沿用该分支。`main` 保留已整理的研究基础，形成可审阅阶段成果后再决定是否合并。当前进度见[研究进展](STATUS.md)，运行安排见[实验计划](EXPERIMENTS.md)。

## H1-v3执行调整（2026-10-18）

## 1. 六个方案怎样安排

| 方案 | 在当前主线中的位置 | 关注的问题 |
|---|---|---|
| 1：先规划逐笔画面，再生成连续过程 | 开环规划基线，必要时用于构造控制条件 | 艺术字变形后的实例定位、计划与实际执行的差距 |
| 2：观察实际结果，再续写 | 生成时的核心流程 | 当前笔是否完成、漏笔、重复笔、提前换笔及错误积累 |
| 3：理解笔迹，交给渲染器执行 | 强基线和执行工具候选 | 正确轨迹的结构保证、风格保持及图像增强造成的偏差 |
| 4：过程理解与生成联合训练 | 训练阶段的核心方法 | 理解任务的知识是否改善生成，共享是否有额外收益 |
| 5：区分决策与执行错误，再局部修改 | 收集真实失败后的扩展 | 同尝试次数下，局部修复能否超过整段重采样 |
| 6：按需检查或训练指导少步生成 | 正确性得到验证后的效率扩展 | 小点、短横、抬笔及先后信息在加速后能否保持 |

第一阶段集中验证方案四＋方案二。其余方案服务于对照和后续扩展，不同时开展六套方法。

## 2. 训练与生成流程

理解任务输入目标文字、指定规范和实际视频前缀，输出实际实例顺序、当前笔、完成程度、首错位置及可执行的下一动作。生成任务输入相同条件和已有过程，输出下一笔的剩余部分、下一笔或短片段。两类任务使用相互连接的过程表示，并通过联合训练检验知识迁移。

生成时采用：

**观察实际视频 → 更新书写状态 → 确定下一动作 → 生成短片段 → 重新观察实际结果。**

一笔未完成时，下一动作可以是继续当前笔。例如“三”的上横只写了一半，即使原计划认为它已完成，也应根据画面继续上横。仅记录已完成笔数无法处理这种情况，状态必须包含活动笔及完成程度。

同时保留空间实例和时间顺序。“三”的上横、中横、下横属于三个不同实例；“横、横、横”无法表达它们是否交换。状态标签应描述实际错误历史，不能自动替换为规范答案。

初始训练目标采用状态/动作文字监督与视觉生成监督。只有观察到明确失败时，再分别考虑区域约束、历史保持或纠错。初始实现、损失和底座候选见[最小研究方案](../experiments/stroke_order_pilot.md)。

## 3. H1、H2、H3分别怎样验证

| 假设 | 实验与证据 | 不能单独作为支持的结果 |
|---|---|---|
| H1：模型理解了实际过程 | SO-01：同终态换序对中恢复实际顺序、定位首错；不完整前缀中识别当前笔与完成程度；全过程对照仅末帧 | 只会回答规范笔顺；只在一个“三”字上答对 |
| H2：过程理解帮助生成 | SO-02B：比较是否联合训练、是否读回实际画面；自由生成整字的严格过程成功率提高，漏笔、重复笔、提前换笔减少 | 只有问答分数提高；只在真值前缀上预测下一步；多次重试但预算不匹配 |
| H3：统一学习有额外价值 | SO-03：联合UMM与分离理解模型＋生成器获得可比数据、条件和计算预算；比较自由滚动结果及成本 | 增加数据、教师标注或推理次数后，仅超过较弱基线 |

H1成立不自动支持H2；H2成立不自动支持H3。若只支持H1，成果范围落在过程理解；若支持H2但尚不支持H3，成果范围落在过程监督与反馈。共享模型的优势只在相应对照成立后报告。

SO-02保留为执行诊断：各方法获得相同正确轨迹或掩码，检查生成端能否执行。它帮助定位瓶颈，不能单独证明H2。

## 4. 第一阶段的范围与起点

采用单字、固定视角、无手部遮挡和清楚的笔画，加入保留基本笔画结构的字体或艺术风格变化。先固定一种规范。完成图像到书写过程、多字、复杂布局和自由行草放在后续检验中。

当前先解决[两项前置门槛](../experiments/h1_state_gate.md)：准确文字状态下能否稳定回答正确；给定完整参考与当前画面时，能否区分已出现的线条及其完成程度。两项得到稳定结果后再加入顺序学习。此时再用“三”的上、中、下与上、下、中同终态对照，检查实际顺序及首次偏离位置，并逐步扩展字符与风格。

H1主实验必须检验同时具备理解与视觉生成能力的UMM本体，当前阶段只调用其理解路径。后续过程任务采用具备视频理解能力的版本；本轮在M5／16GB本机使用Show-o2-1.5B-w-video-und完整检查点检查文字接口与静态线条状态。已有[像素实验](../experiments/process_probe.md)用于数据构造；[Janus-Pro诊断](../experiments/h1_umm_diagnostic.md)的33题及33题位置对照保持原记录。Qwen3-VL仅保留为[外部辅助对照](../experiments/h1_diagnostic.md)。

## 5. 评价和推进条件

分别报告最终字形、笔画实例顺序、笔内方向、未完成即换笔、漏笔、重复笔和历史内容保持。整字结果来自自由滚动生成；每一步使用真值前缀的结果单列。遮挡或采样不足时保留不可观察标签，并报告覆盖率。

比较联合训练和实际反馈时，至少保留“仅生成训练＋无反馈”“仅生成训练＋读回画面”“联合训练＋无反馈”“联合训练＋读回画面”四种设置。仅生成训练组保留底座已有的理解能力，但不增加本题的过程理解训练。输入适配、可训练参数和推理计算差异需说明。

切换反馈时，生成器维持连续性所需的历史视觉条件保持一致；主要改变理解分支是否读取实际结果并更新后续动作。无反馈组按预先计划推进，反馈组依据观测调整。理解调用的额外成本需计入，避免把更多视觉条件或计算混作训练协同的收益。

已经发生的错序不能通过后续添墨抹去。离线片段重做需要单独记录位置、次数及成本；在线过程保留已发生的失败记录。

先确认H1，再用SO-02定位执行瓶颈、用SO-02B检验H2，最后完成H3对照。多字和效率扩展由前述结果决定。负结果也用于收缩或调整方法，工作标题不作为必须证明的结论。
