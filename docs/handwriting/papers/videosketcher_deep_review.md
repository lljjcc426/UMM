## 第一遍｜三句话

纯图像/文生视频模型容易生成已完成的素描，却不擅长生成有顺序、有阶段、受风格控制的绘画过程。VideoSketcher 将 LLM 的语义绘制步骤规划与 Wan2.1 视频扩散生成结合，通过合成几何图形阶段训练和仅 7 个真实艺术家素描的第二阶段 LoRA 调整，另提供压缩后的自回归共同绘画路线。其直接展示了视频模型生成“逐渐出现的绘画”的已有能力，但没有建立中文规范笔顺、笔画实例 ID 或绝对顺序正确率。

## 第二遍｜五问

### Problem：准确的任务边界

输入：自然语言画什么/先画什么，或自然语言加左上笔刷颜色/风格条件图。输出：从空白画布逐步出现内容的素描视频；自回归模式支持多片段延展及用户交互。与“给定规范汉字笔画事件、保证笔锋方向”有较大差别；前者步骤往往对应语义对象片段，后者需要指定笔画的离散事件身份。

### Motivation：为什么现有视频生成会出错

常规文本到视频生成偏向画面外观与动态语义，缺少对“每一步画哪一部分”的结构约束，直接少量真实绘画示例训练又样本稀缺。作者以几何基元的可合成顺序监督先学“逐步添加”，再小样本迁移素描纹理与风格。可检验的关键是语义计划被视频真实执行到何种程度。

### Contribution：针对的不足

- 用显式 LLM 计划把绘制内容拆成有序语义阶段。
- T2V 与笔刷条件 I2V 分支采用 Wan2.1-14B 与 LoRA 的两阶段训练：合成几何基元→真实艺术家草图；官方声称第二阶段仅 7 个真实素描。
- 提供由 Wan2.1-1.3B / CausVid 路线蒸馏的自回归生成，延展片段及交互式共同绘画。

以上机制中的预训练视频底座、LoRA、LLM 计划、蒸馏均有更早前作；贡献评判要落实到特定序列素描任务、合成阶段监督和视觉执行的证据。

### Method：三个公开可运行接口

1. T2V：将“概念＋ordered drawing steps”放进 prompt，Wan2.1-T2V-14B 加载作者的 VideoSketcher_T2V LoRA，生成序列绘制视频。
2. Brush-Controlled：输入第一帧左上带笔刷颜色/样式标记的图，与目标绘制计划一起送 Wan2.1-I2V-14B-480P 加载 VideoSketcher_I2V LoRA，产生相同风格的新绘制序列。该 I2V 用于风格控制，不能与任意起始帧一致性直接画等号。
3. AR：Wan2.1-T2V-1.3B 路线用 VideoSketcher_AR 权重延长视频；多 rollout 每段 81 帧且重叠 9 帧，n 段帧数 n×81−(n−1)×9。

训练示例中，T2V stage 1 的 dataset_repeat=100 / epochs=7，stage 2 同为 100 / 7；I2V 的合成与真实 stage 分别 1 / 7、1 / 13；自回归脚本例示 100 / 27。它们是作者 shell 调用，不保证在所有版本都代表论文最终设定。精确 lr、梯度累计、LoRA target modules 和损失项需阅读训练脚本后填，不凭经验猜数值。

## 第三遍｜深入问题

1. **语义阶段≠汉字笔画实例。** “先画独角兽身体再画腿”与“字符第 k 笔第 j 个横画”没有天然一一对应；可直接尝试“二、三、王、玉”等重复笔类的同末帧负例。
2. **计划≠执行。** 指令中明确序列不保证视频里顺序正确；用 OCR/最终画面判断尤其容易误判。
3. **少量真实数据背后有大量合成监督和强预训练底座。** 比较低样本能力必须把两阶段已有监督、预训练和计算报告清楚。
4. **AR rollout 长期一致性。** 延长视频可出现重画旧笔、已写笔消失、字符实例漂移；请在固定时长和同计算预算下与整体视频模型对照。
5. **评测与可见性。** 在时间采样率不够时，短笔可能一帧出现多个；区分模型真正并笔与观测不足。
6. **适合哪一研究方向？** 它直接削弱“视频逐步绘画无人做”新颖性，适合作为计划+视频执行强基线；真正可能的新问题是同末帧冲突历史、规范实例绑定与可验证的在线闭环修正。

## 八项标准笔记

1. Problem：受语义步骤约束的序列素描视频。
2. Motivation：通用视频模型和小真实数据对渐进绘制过程约束有限。
3. Contribution：合成几何规则→真实素描的两阶段 LoRA；LLM 绘制计划；笔刷控制与 AR co-drawing。
4. Method：prompt/条件图→LLM 步骤→视频扩散 LoRA→绘制过程视频；AR 支线蒸馏与重叠滚动。
5. Experiments：仓库可复核模型、脚本、硬件与示例；**主质量表/全部消融数值待核**，不可编造。
6. Limitations：笔画语义和规范汉字目标不同、模型执行与 prompt 可能失配、AR 外观/累积误差、可用性依赖 GPU。
7. Insights：引入显式实例计划与实际视频回读，测试固定完整画面、改变事件历史的硬反例；和原始 VideoSketcher 等条件比较。
8. 一句话：VideoSketcher 已证明序列素描视频方向有强直接前作，汉字笔顺规范执行仍需新的严格任务定义与实验。
