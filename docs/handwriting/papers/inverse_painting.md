# Inverse Painting 精读：从语义规划到局部视觉执行

来源：[论文v2](https://arxiv.org/html/2409.20556v2)。
继承既有方法/附录核查；本次没有运行生成模型。

## 方法信息流

目标图、当前画布 → LLaVA决定下一步画什么 → 区域掩码决定画哪里 → 扩散模型更新画布 → 新画布进入下一步。

它是外部理解与生成模块组成的系统，不等于一个原生统一模型；输出是画布变化步骤，不是完整笔尖运动。

## 有解释力的消融

| 配置 | 更新区域IoU |
|---|---:|
| 完整 | .418 |
| 去文字规划 | .400 |
| 去区域掩码 | .175 |

它提示具体空间执行条件在该任务很重要，但不能得出语言在所有任务不重要。不同分支可能仍受到共有条件的信息影响。

附录每次更新为25步去噪、A100约4秒；20秒对应画作进度条件，不能误写为墙钟耗时。完整视频还要计入多轮规划、掩码、解码和重试。

## 与中文书写的相同与不同

相同：已有内容不能随便消失；规划需要结合当前视觉状态；局部更新应与指令对应。
不同：绘画通常有多种有效次序，规范写字可能指定先后；画布块更新不提供落笔/抬笔；回退的离线制作与不可撤销在线流不同。

## 待验证的问题

慢规划器与快局部执行器是否有效？可只在字符/部件切换时做高层规划，但要与固定频率、随机触发、同预算外部VLM比较；若状态检测本身仍每帧运行完整模型，不能宣称省掉理解成本。

[OnOff](https://arxiv.org/abs/2608.03198)、[VACE](https://arxiv.org/abs/2503.07598)、[Wan-Move](https://arxiv.org/abs/2512.08765)补全了物理/掩码/轨迹强基线。UMM不是预设赢家。
