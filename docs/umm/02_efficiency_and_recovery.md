# UMM 效率与可靠恢复

本页以已有调研为基础。所有数值是论文特定协议报告，非本次实测。

## 分解成本，避免误用“资源”

`总时间 = 条件编码 + 理解/规划 + 去噪执行 + 解码/渲染 + 检查 + 重试 + 数据搬运`。

- 生成速度不等于播放速度。
- 少NFE不等于总时间同比减少；guidance可改变一次采样的实际模型调用数。
- KV缓存仅是显存的一部分，权重/激活/解码器都需要计入。
- 训练成本包括教师采样、错误筛选和评分，不只学生更新。
- 稀疏掩码条件不等于稀疏执行；只有实现跳过计算才能主张这部分节省。

## 已有强基线

| 文献 | 已有机制 | 对书写研究的约束 |
|---|---|---|
| [Hyper-Bagel](https://arxiv.org/abs/2509.18824) | 文字投机、图像多阶段蒸馏 | “少步UMM”已有直接前作 |
| [Flash-Unified](https://arxiv.org/abs/2603.15271) | 按任务裁剪、动态跳层、guidance与缓存 | 需比较关键小笔画是否比普通场景更易受损 |
| [UniCache](https://arxiv.org/abs/2609.32831) | 任务/类型区分的KV压缩 | 状态相关压缩必须超越通用类型策略 |
| [TeaCache](https://arxiv.org/abs/2411.19108) | 去噪步骤之间复用特征 | 全局变化不能直接替代笔事件重要性 |
| [RecA](https://arxiv.org/abs/2509.07295) | 重建对齐、低标注监督 | 重建成功不证明过程合法 |

## 恢复研究

[UMM-Reflection](https://arxiv.org/abs/2609.35767)已联合优化文字反思与图像修订；[SCO](https://arxiv.org/abs/2610.10400)关注多轮状态与新事件；[AdaViG](https://arxiv.org/abs/2607.10004)选择有益的视觉步骤；[MIRROR](https://arxiv.org/abs/2602.18746)强调反馈必须与视觉证据绑定。

所以，单纯“生成—检查—重画”不够。应分别评价：是否检测、反馈是否正确、是否落实修改、是否损坏原有正确状态、是否真的改善后续任务。

## 候选问题（未验证）

“按语义事件调用完整理解”的假设：简单常规笔画可由轻量执行器处理，转字、转部件、异常或不确定事件触发UMM。必须对照定期/随机检查、同预算通用缓存、理想触发上界；状态提取和触发头成本全部计入。

“保留关键状态的缓存”假设：微小短笔可能决定字义，低平均注意力不证明无用。用关键短笔与无关纹理的等面积扰动做控制实验。如果普通缓存已达到同等效果，不应强行增加事件模块。

“对事件有意识的少步生成”假设：连续坐标偏差与离散抬笔错误的风险不同。先用普通一致性/MeanFlow类学生测试，避免把未经训练的1步差距当作不可逾越上限。
