# UMM 架构、视觉思考与协同：沿用既有调研的结构化笔记

## 架构选择

| 路线 | 代表来源 | 关键取舍 |
|---|---|---|
| 图文统一离散自回归 | [Chameleon](https://arxiv.org/abs/2405.09818)、[Emu3](https://arxiv.org/abs/2409.18869) | 图像token长度与精细视觉信息 |
| 分开视觉编码、共享序列模型 | [Janus](https://arxiv.org/abs/2410.13848)、[Janus-Pro](https://arxiv.org/abs/2501.17811) | 避免表示冲突但仍需知识交换 |
| 文字AR、图像扩散/流 | [Transfusion](https://arxiv.org/abs/2408.11039)、[BAGEL](https://arxiv.org/abs/2505.14683)、[Show-o2](https://arxiv.org/abs/2506.15564) | 两类损失/专家共享多少、在哪里交互 |
| 多模态离散扩散 | [UniDisc](https://arxiv.org/abs/2503.20853) | 不以逐token因果顺序为唯一范式 |
| 像素/原生统一接口 | [UniModel](https://arxiv.org/abs/2511.16917)、[SenseNova-U1.5](https://arxiv.org/abs/2609.11929) | 接口统一仍需验证信息保持和任务能力 |

这是代表设计，不是互斥且完备的分类；使用相同名称的不同版本要单独定位。

## 图文交错推理

可用 `问题/观测 → 文字操作 → 生成视觉状态 → 观察/反思 → 后续状态 → 答案` 表示。视觉状态可以是图片，也可以是潜在表示。[Zebra-CoT](https://arxiv.org/abs/2507.16746)提供轨迹数据；[ThinkMorph](https://arxiv.org/abs/2510.27492)研究互补视觉思维；[Monet](https://arxiv.org/abs/2511.21395)、[LatentUM](https://arxiv.org/abs/2604.02097)探索潜在视觉步骤。

这里至少有四类不同错误（本库的诊断划分）：
1. 输入看错；
2. 下一动作或中间表示选错；
3. 计划对但视觉生成执行错；
4. 视觉证据正确却被后续文字忽略。
同一方法可能只改善其中一类，不应只用最终答案总分推断全部机制有效。

## 如何检验协同

[VGUBench](https://arxiv.org/abs/2602.23711)将文字回答、视觉回答与直接绘图控制分开；[UEval](https://arxiv.org/abs/2601.22155)针对联合输出；[WEAVE](https://arxiv.org/abs/2511.11434)针对多轮交错。研究时应选与主张相符的协议。

本库建议的因果对照：
- 固定文字前缀，只替换中间图里决定答案的状态，后续答案是否正确随之变化？
- 保持任务状态，改变纹理/风格，答案是否稳定？
- 固定尝试数，对照重新采样与针对性修复。
- 为模型提供正确诊断、正确修复图，分别定位检测瓶颈和执行瓶颈。
这些是实验建议，不是已经完成的模型能力结论。

## 协同不一定正向

[GapEval](https://arxiv.org/abs/2602.02140)显示功能统一不保证知识一致；[协同控制研究](https://arxiv.org/abs/2609.01607)则在特定设置中观察到正迁移。两者不必矛盾：架构、数据、初始化和任务知识不同。

[UniMRG](https://arxiv.org/abs/2601.21406)、[SGT](https://arxiv.org/abs/2605.18714)、[DIVA](https://arxiv.org/abs/2605.25328)提供多表征、语义调优和差异化表示路线。添加分割、深度或OCR不是全新机制，应说明为何对过程状态有效。
