## 1. 研究问题（Problem）

多模态agent在程序化画布上能否逐笔临摹复杂汉字书法，并兼顾笔画、顺序与审美？

## 2. 现有方法不足（Motivation）

文字识别正确不保证字形布局、粗细、连笔和长程工具规划正确；普通图生成不能代表受限绘制工具条件的agent能力。

## 3. 核心创新（Contribution）

参考图visionmessage、tldraw MCP逐stroke任务，规范几何对照与视觉rubric/MJ1两两偏好；公开88任务输入和部分规范SVG/中线字段。

## 4. 方法流程（Method）

输入与输出：referenceimage（禁止程序直接读像素）+workspace/code→create/update/delete/clear/capture/save工具序列→最后save画布；允许删改/重画，缺少完整日志时不能默认不可逆的连续真实笔序。

方法框架与模型结构：OpenHandsPythonSDK调度，tldraw points(x,y,z)/z压力0–1+size s/m/l/xl；视觉评审matchedX/referenceN、orderY/X、6维风格差异→1–5。MJ1 Tinker轮转所有pair。不是新训练的video或UMM骨干；压力为工具参数，未校准真实力。

数据集与分布：卡/网站称88characters/20masters；当前datasetsserver全88行实际82uniqueUnicode字符、18书家label，笔数10–25。reference来自Kaggle53K+图/200+书家；网站明确规范SVG/medians来自MakeMeAHanzi9574字，非名家实写时序。实际schema多strokes_svg/medians/calligrapher_label；39/88行stroke_count与两类几何条数不同，SVG/median条数彼此相同。逐行明细另存，不在无证据下判为评分错误。

## 5. 实验结果（Experiments）

主要基线：GPT5.4、ClaudeOpus4.6、KimiK2.5、GLM5；缺规则规范SVG回放、图生成+向量化、动作模型对照；工具能力与外部知识访问预算需同条件。

关键指标：StrokeRecall=X/N、StrokeOrder=Y/X（漏笔不进入order分母）、Fidelity1–5六维rubric、MJ1pairwin；matched定义/空匹配分母/视觉judge完整prompt/采样不公开。不能用高order单独保证全字正确。

实验条件：未见训练阶段；每任务时限/最大token/重试/模型API日期/seed/judge版本/人工一致性尚缺。HF README revision d3f189f，datasetsserver为当前缓存接口未固定revision，88行观察不能自动归同一gitrevision。网站JS当前公开payload只作协议与来源证据，未调用未公开权限数据。

结果及解释：发布方表GPT recall86%/order82%/FIDELITY2.2/5/pair75%；Opus89%/77%/1.6/60%，Kimi83/79/1.3/34，GLM71/78/1.3/30。不是独立重评分；全模型审美<2.5，能力分项排序不同。88任务作者统计与当前82字/18标签差异尚待版本说明。

消融实验：未见同工具/预算的分组件受控消融；四agent排名和展示case不等于机制因果实验。资源审查通过全88行统计验证字段、唯一数、几何数；未下载模型输出或重评分。

所有分数均为作者报告；条件、版本和样本数不同的数字不得直接排名。
