# T6：实际事件状态与记忆比较

本轮复用完整Show-o2检查点的冻结逐帧融合特征。比较对象为独立读出头和状态记忆；UMM本体没有通过联合训练学习新的顺序知识。数据契约、超参数和门槛见[协议](h1_t6_early_history_protocol.md)。

## 信息与理论假设

若同目标、同参考的两段过程在决策时具有相同局部输入X，而实际历史Y不同，确定性函数f(X)只能输出同一答案。因而B3对这种配对的“两条都正确”上界为0。普通头输出不同答案时须检查随机性、未来输入或判分。该限制不要求B3单段正确率为0，也不说明其当前完成状态识别失败。

完整历史包含早期不同的笔画实例首次出现时刻，因此可以恢复不同顺序。B4的完整历史与短窗口共享权重、绝对时间戳和当前输入，差异在可访问历史长度。Full优于Short只支持额外历史信息有用；Full与在线Ledger都访问完整过去，才能进一步比较历史表示。

固定单色累积墨迹中，同一采样间隔完成的两笔可以产生完全相同的观察序列。源日志即使记载明确顺序，模型也无法从这些输入分辨。未来继续添墨无法复原这个已经丢失的关系。真实顺序日志、可观察偏序和规范顺序分别保存。

## 共享空间接口与局部读出

A用完整参考、规范ID、类型和四分之一画布的粗位置预测实例软区域；查询不含实际源顺序或精确mask。B读取当前／前一冻结特征及真实RGB增消变化，预测当前、新增、消失墨迹。A+B只有一套共同权重。每帧、每实例以相同软区域池化64维当前、64维相邻特征差、64维参考差、3维墨迹状态和1维绝对秒数，共196维。主输入白名单在h1_early_history_io.py明确实现。

M1沿用逐时刻普通头，其排序、状态和置信度只依赖当前196维向量。M2沿用256维、2层、4头因果Transformer；同一时刻各实例可以通信，任何未来时刻均被遮蔽。M3只保留最近4/8个已观察向量，窗口第一帧的变化仍由其真实前驱计算，时间不归零。

排序监督只比较已经出现、起笔观察区间不同的实例，不对合并起笔施加任意总序。所有方法的连续进度与未出现／部分／完整类别分开保存；规则D采用类别转换的完成状态，不能用其动作成绩代替进度回归可靠性。方向证据和抬笔证据也分开，画面无笔尖时抬笔始终unknown。

## 在线事件表

M4使用M1当前局部状态与B的新增墨迹预测，每帧只更新当前及此前事件。存在概率≥.5、区域新增墨迹≥.02且有前一观察，才能确认起笔区间。首次出现但缺新增证据时保留不确定实例；后续不以规范补齐，也不凭将来完成图倒填起笔时间。

事件表保留instance_id、first_observed_interval、last_observed_progress、geometry_state、onset_confidence及方向证据。不同确定区间建立先后关系；同一区间多实例保留为未定组。已记录的先后不会因后续静态画面被替换成规范顺序。没有观察到的实例不写入表。

兼容输出event_order：能确定唯一顺序时给ID数组，否则null。同时输出onset_intervals、confirmed_precedence、unresolved_order_groups、uncertainty_reason，保留局部确定的知识。未知历史下D的request_observation需要结合recovery解释：缺失过去观察才有机会补证，后续空白／添墨无法恢复已丢失关系。事件表置信度是确定性证据标记，不能当成已校准的答对概率。

M5只把正确实例区域及从实际观察读出的起笔区间提供给同一Ledger，用于检查记忆逻辑。M0通过RGB与独占实例区域读出历史，两者均有特权输入，单独列上界。

M1/M2保留现有单排序分数与可观察置信头，不新增偏序预测头。可观察置信≥.5才输出唯一排序；低于门槛时event_order=null、全部已见实例暂列未定，因此这两种头未必能保留正确的局部偏序。该能力差异作为实际结果报告，不用oracle关系补齐其输出。置信度监督预测“历史可观察”，不能直接解释为排序答案正确。

## 比较的实际边界

M1/M2只按Dev loss选一次检查点，12轮曝光相同；M3/M4不另训练。M2与M4原始历史相同，但后者包含在线规则与事件缓存，参数、运算、记忆需求不同，分别报告。预测区域与正确区域下使用同一头的输入替换只做瓶颈诊断，不等同重新匹配训练的oracle最优模型。

清楚D0没有手部遮挡、轨迹回描、擦除、漏笔或字体变化。五笔图形不等同规范汉字泛化，三笔“三”仅单列诊断。单seed和20个测试几何的区间不能证明跨字体或训练随机性的稳定性；H1完整验收、H2反馈生成与H3统一训练均待后续独立证据。

候选状态字段与限制见[数据接口](../../data/h1/early_history_v1/state_schema.json)。标记history_not_identified时，恢复字段尚不能判断是读取失败还是过去信息缺失；它不能保证请求未来画面有效。merged_onset_interval在真状态中表示已经丢失的过去关系，在预测状态中仍可能是起笔漏检造成的错误诊断。
