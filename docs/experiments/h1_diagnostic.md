# H1：实际过程理解的首轮本机诊断

## 1. 先回答什么

先拆开三个问题：模型看到了哪些笔、哪些完成了；它能否根据实际顺序判断违规及首错；在这些判断之下，它选择继续当前笔、开始下一笔、停止还是补充观察。此次只输出动作标签，不运行视频生成，也不检验联合训练收益。

首轮使用冻结的小型VLM建立诊断基线。H1通过仍需更多字、结构和风格上的证据；本次结果不证明UMM已经具备相应能力。

## 2. 模型与输入

- 模型：[Qwen3-VL-2B-Instruct](https://huggingface.co/Qwen/Qwen3-VL-2B-Instruct)的[MLX社区4-bit转换](https://huggingface.co/mlx-community/Qwen3-VL-2B-Instruct-4bit)。模型未在本项目上训练。
- Hugging Face版本：`9c4f5209e57b31f4b9dfba735de3fb983739c9cc`；下载使用[ModelScope镜像](https://modelscope.cn/models/mlx-community/Qwen3-VL-2B-Instruct-4bit)，镜像版本`f338871b6a559fe9dc10ea3cf041da8abaff3c50`。下载权重与HF该版本的LFS摘要一致。
- 运行环境：Apple M5、16GB统一内存、macOS 26.6、Python 3.12.14、MLX-VLM 0.7.8、MLX 0.32.4、Transformers 5.20.0。
- 每次独立输入；贪心解码，`temperature=0`、`seed=0`、最多512个输出token；不进行格式重试、结果修补或择优挑选。
- 输入是按时间排列的独立图片，未使用原生视频接口。每张原图224×224，第一张为完整目标参考，随后才是实际过程。预处理设置、token数和MLX内存记录保存在运行文件中。

数据为12个源案例、33个输入，包含“三”“十”的完整/半笔前缀、换序、反向和提前换笔。四种条件分别为全部离散过程帧、仅末帧、空白首尾帧、准确文字状态。详见[数据说明](../../data/h1/pilot_v1/README.md)及[预览](../../data/h1/pilot_v1/preview.png)。完整提示与标签在模型推理开始前确定。

同终态对为`c04/c05`（三）和`c09/c10`（十）。另用`c08`与`c04`区分相同终态下的反向运笔。模型明确得到指定规范，因此它的任务是读取实际发生的过程并比较规范。

## 3. 指标解释

| 指标 | 正确条件 |
|---|---|
| 可见实例 | `seen`集合完全一致 |
| 完成状态 | `finished`及`unfinished`两个集合均正确 |
| 实际顺序 | `order`完全一致；证据不足时应给`null` |
| 笔内方向 | 所有可见笔的方向映射正确 |
| 提前换笔 | `early_switch`的序号、无错或不确定状态正确 |
| 完整判断 | `status`、`first_error`、`error_type`同时正确 |
| 下一动作 | `next`与`target`同时正确 |
| 全项正确 | 该条件需要评价的全部字段正确 |

另单列总体合规状态和首错位置，避免严格联合指标掩盖局部能力。JSON解析失败计为该输入的各项错误。文字状态对照不评分已经给出的观察字段。

动作遵循预设的保守策略。要求不确定时补充观察，属于实验决策规则；不能将此动作分数解释为真实生成环境的最优控制。四组覆盖案例数不同，组间均分不构成配对因果比较。

## 4. 2026-10-16结果

**本次设置未通过H1。** 33个首轮输入全部运行，31个回答可解析为JSON对象，2个因输出持续枚举数字而达到512 token上限。所有原始回答均保留；没有重试或人工补全预测。

| 条件 | 可见实例 | 完成状态 | 实际顺序 | 方向 | 完整判断 | 动作＋目标 | 全项正确 |
|---|---:|---:|---:|---:|---:|---:|---:|
| 全部离散过程帧 | 1/12 | 0/12 | 1/12 | 1/12 | 5/12 | 0/12 | 0/12 |
| 仅末帧 | 5/11 | 5/11 | 0/11 | 0/11 | 0/11 | 0/11 | 0/11 |
| 空白首帧＋末帧 | 5/5 | 5/5 | 0/5 | 0/5 | 0/5 | 0/5 | 0/5 |
| 准确文字状态 | 不计 | 不计 | 不计 | 不计 | 2/5 | 0/5 | 0/5 |

两组同终态换序对均未同时恢复正确的实际顺序。末帧与首尾帧的顺序指标评价能否承认证据不足，不要求从静态图猜出真实历史。

不能把表中5/12的判断结果理解为可靠纠错：全部31个可解析回答都输出了`status=valid`，其中一些正例的判断碰巧正确，观察字段仍错误。模型也在全部31个JSON中遗漏`target`。为区分字段遗漏与动作选择，额外保留`next_action`单字段分数：过程帧2/12、文字状态1/5，其余0；原有动作＋目标指标保持不变。

具体错误包括：

- `c00-sampled_frames`：实际过程只有空白，回答却称三条横均已完成并选择`done`，与参考图的完整状态一致。
- `c01`和`c02`：半条上横与完整上横没有被可靠区分。
- `c04`、`c09`等过程输入：输出数字编号作为笔画ID，未使用约定实例；`c05`、`c08`持续枚举到截断。
- `c05-oracle_state`：准确状态已明确上→下→中，仍判断`valid`；`c07-oracle_state`已给出提前换笔，却仍判断`valid`。

原始配置：[run.json](../../results/h1/qwen3_vl_2b_4bit/pilot_v1/run.json)；全部回答：[predictions.jsonl](../../results/h1/qwen3_vl_2b_4bit/pilot_v1/predictions.jsonl)；逐项对照及汇总：[scores.json](../../results/h1/qwen3_vl_2b_4bit/pilot_v1/scores.json)。

### 单项提问补充

| 单项任务 | 结果 | 能支持的判断 |
|---|---:|---|
| 可见实例，无参考图 | 0/4 | 去掉参考图仍未解决实例绑定；不能把错误全部归于参考图 |
| 可见实例，有参考图 | 0/4 | 在这四个配对案例中仍不可靠 |
| 完成状态 | 0/4 | 两个集合同时正确的案例为0 |

| 准确状态，只问动作＋目标 | 0/5 | 三例重复输出至截断，另两例动作错误 |

## 5. 当前解释与下一步

已看到的能力是简单场景中的线条计数，以及短自然语言条件下“未完成应继续”的判断。当前结构化过程任务没有可靠完成，失败同时涉及实例ID绑定、时序汇总、规则应用和输出遵循。仅凭这些结果，无法把所有问题归为视觉能力不足，也无法认定量化、模型规模或推理后端中的某一个因素是原因。

接下来仍在H1内推进，优先顺序如下：

1. **先测观察与实例绑定。** 将不提供目标字名称的图像描述、中文位置名称、固定实例ID三种回答形式作配对比较。先证明模型能把当前图中的具体线条对应到实例，再要求它输出长过程状态。
2. **分开测规则和动作。** 准确文字状态下，分别问首错、完成程度和下一动作；比较自然语言与短结构化输出。基础半笔问答已答对，值得检验其能否稳定迁移到状态接口。
3. **再测时间顺序。** 使用相同终态的正序/换序、正向/反向配对；对比相邻帧、少量关键帧和全部进度帧，明确增量变化在哪一环丢失。关键帧条件必须保留所评价事件，不用不可观察输入强迫模型猜测。
4. **接口可靠后扩展覆盖。** 再增加点、折、包围、更多交叉、未见字和风格；固定独立留出集，并考虑另一实现或另一模型作交叉核查。当前两个字、单一线条渲染的结果不能外推到真实书写或UMM。

本次可以确认本机资源足以进行小型VLM诊断。尚未得到足以让该模型担任书写过程反馈控制器的证据，暂不进入H2生成能力和H3统一学习收益验证。

## 6. 复现

在Apple Silicon机器上准备Python环境与本地模型目录；权重保留在已忽略的`checkpoints/`中，不上传GitHub。

```bash
python -m pip install -r requirements-h1.txt
hf download mlx-community/Qwen3-VL-2B-Instruct-4bit --revision 9c4f5209e57b31f4b9dfba735de3fb983739c9cc --local-dir checkpoints/Qwen3-VL-2B-Instruct-4bit
python scripts/h1_dataset.py
python scripts/h1_run_mlx.py --output results/h1/qwen3_vl_2b_4bit/new_run
python scripts/h1_score.py results/h1/qwen3_vl_2b_4bit/new_run/predictions.jsonl
```

默认模型目录为`checkpoints/Qwen3-VL-2B-Instruct-4bit`。可用`--model`指定同一模型的本地目录；换用其他模型时需要另行记录身份、配置和适配。输出目录要求为新目录，以保留每次尝试。数据构造可确定性复现，后续修改协议须另建数据版本。
