# UMM与中文书写生成：综合分析

本文概述UMM与中文书写过程生成的研究范围、主要方法及开放问题。详细证据见专题分析与文献目录。

## 1. UMM：统一什么，以及为什么不自动产生协同

UMM研究涉及输入输出接口、视觉表征、生成目标、共享参数、数据与训练调度、跨任务推理及评价。统一成一个模型不意味着理解和生成必然互相帮助。

离散AR、连续扩散／flow、混合建模、分支或专家共享分别解决不同约束。视觉语义足够识别一个字，却可能缺少生成细笔所需的空间细节；像素重建丰富也不自动形成规则理解。需要控制额外数据与计算，才能判断跨任务收益来源。

入口：[UMM总览](umm/00_overview.md)、[架构与推理](umm/01_architecture_and_reasoning.md)、[完整综述](../archive/local/2026-10-15/UMM研究综述.md)、[深入机制分析](../archive/local/2026-10-15/深度专题分析.md)、[全部UMM及相邻机制文献](umm/literature.md)。

## 2. 中文书写：把终态字形与实际过程分开

研究链条包含静态字体、在线轨迹、离线到在线恢复、笔画实例、物理渲染、过程视频及理解生成闭环。

InkSight、UniCalli限制了“读写联合／中文统一生成首次”的主张；XMP-Font与DP-Font说明笔顺先验和相关损失已有研究；LVGM、OLHWG、DiffInk说明逐笔与多字生成已有直接前作。OnOff连接轨迹、接触和累积墨迹，仍需核对最终增强画面是否忠实于控制。

值得验证的是：模型能否观察实际前缀，绑定具体笔画实例，选择正确下一笔，并让实际画面执行。最终OCR、静态FID、标准笔顺问答均不能独自证明这一点。

入口：[笔顺专项](handwriting/05_stroke_order_umm.md)、[重点研究与修订](handwriting/01_focused_update_2026-10-15.md)、[能力矩阵](handwriting/02_capability_matrix.md)、[中文书写研究分析](../archive/local/2026-10-15-中文笔顺视频/中文笔顺视频与UMM深度调研.md)。

## 3. 视频研究和真实数据已经提供哪些约束

VidScribe与VTR-Bench已有中文文字、手写演化及反馈生成研究，不能将“没有相关视频文字基准”作为结论。它们的转录、结构、持续性评价仍与指定规范下的逐笔实例顺序不同。

此前公开样例核查中已观察到过程问题，但8段定性样例不支持全模型错误率或所有模型都失败的结论。保存[核查说明](../archive/local/2026-10-15-中文笔顺视频/公开视频样例核查.md)及带帧号的样例图，模型标签沿用公开数据集。

OpenHandWrite提供真实笔画级过程研究资源。真实记录是实际行为，不自动都是规范金标准；CASIA文件中的顺序、时间和压力字段也需按具体格式区分。静态艺术字不能提供唯一真实历史。

入口：[数据与标准](handwriting/03_data_and_standards.md)、[OpenHandWrite卡片](handwriting/papers/openhandwrite.md)。

## 4. 效率作为第二阶段研究

效率研究包括少步生成、缓存、历史压缩和错误恢复。当前先确定错误来自表示、规划还是执行，再研究如何降低对应成本。

小笔画面积小、持续短，平均像素误差或一般注意力重要性可能忽略它；这是研究动机，不是已证明特定缓存策略有效。比较应匹配数据、推理次数、重采样及预处理成本，报告固定正确性目标下的成本。

入口：[效率与恢复](umm/02_efficiency_and_recovery.md)、[强基线与效率](handwriting/04_baselines_and_efficiency.md)、[实验跟进](project/EXPERIMENTS.md)。

主目录保存每项研究的声明、方法、问题、结果、边界、来源和历史核查。尚未核查或未单独摘录的信息在文献表中注明。

当前最需要实证回答的三点：过程输入是否真的被利用；这种理解是否改善实际生成；共享是否比信息与预算相同的组合系统更有优势。反例数据、严格实例顺序指标和强基线比增加模块名称更关键。
