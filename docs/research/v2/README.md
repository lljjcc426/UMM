# 研究设计 v2：笔画事件驱动的汉字书写视频生成

版本：`stroke-video-v2`，2026-10-27。研究目标与实施协议的当前版本。方法、规模与门槛仍属设计；已有ENV-01原生接口和最小训练/重载实测，以及DATA-01/EVAL-01受控CPU工程证据；人工核验尚缺，无已审定金标准、通用评分器或方法对照结果。

## 1. 核心定位

**提出并验证提升汉字书写视频真实笔顺执行的方法，在已有视频UMM上后训练得到对应模型。** 首篇以生成方法和模型效果为核心；数据及评价提供可信证据；共享训练是重点假设；自纠错、复杂行草、真实手笔和效率是条件性扩展。无需从零训练视频基础模型，也不以单纯更换模型或普通微调作为充分贡献。

工作性题目：**面向汉字书写视频的笔画事件理解与生成执行一致性**。题目描述研究对象，不预先承诺全字库正确、首次、SOTA或自主纠错已实现。

实际需求是：给定文字、独立风格参考和明确规范，得到可见逐笔形成、最终可辨、风格一致的视频；另研究在不完美的实际前缀下继续生成。固定字库动画有成熟程序方案，不能以替代已有笔顺播放工具为唯一价值。只有当风格适配、视觉执行或真实前缀处理存在可复现不足，才论证学习型方法的必要性。

## 2. 相比 v1 的实质调整

| v1风险 | v2修订 |
| --- | --- |
| 容易以缺少专用模型作为创新理由 | 以同协议强基线的具体失败建立动机；研究边界由近期直接前作约束 |
| 零样本失败容易被当作机制缺陷 | 新增同数据普通SFT、顺序文本条件、轨迹渲染及硬空间控制；先排除仅缺领域数据 |
| 前缀理解、评测和自纠错可能分散主线 | T协议从空白自由生成作为主结果，P协议解释机制，O协议给执行上界；恢复可选 |
| 共享、事件条件、反馈一起变化 | 将事件约束的有效性、共享的增量、真实反馈的增量拆成不同实验 |
| 64/512字可能被误读为建成Benchmark或充分样本量 | 保留为预算起点；功效、跨字/风格/渲染器划分与模型输出域校准必须单独验收 |
| 合成评价器通过后直接评自由生成 | 增加开发集实际生成视频的独立双人标注和观察器域迁移检查 |
| 强制按一笔一个片段可能泄露事件边界 | 主协议用预先固定窗口和公开上下文预算，事件边界触发另设对照 |

## 3. 证据与新颖性边界

[近期直接前作核查](source_audit.md)给出原始来源和本轮阅读深度。VideoSketcher已有计划引导的逐步RGB绘画，作者披露多笔同帧和提示偏离；HiSAC已有部件/笔画层级风格建模及轨迹/静态图生成；OnOff已有轨迹、物理笔刷、图像增强和机器人执行；逐部分Sketch Agent已有画布反馈与过程奖励。已有笔顺工具也能确定性输出动画。

因此，候选增量应落实为：**将规范笔画的空间身份、实际完成状态及笔内进度约束到生成RGB的新增墨迹上，并证明这种约束在同数据普通适配和强分离系统之外具有价值。** 单独增加事件token、一个loss或反馈调用都不自动形成新颖性。

本轮没有确认完整匹配“汉字规范笔顺、原生RGB过程、理解生成统一、实际视频严格评价”的公开工作；这是已核来源范围内的判断。不能由缺少完全匹配论文推断目标能力无人实现。

## 4. 要回答的假设

| ID | 假设 | 必须有的反证/对照 |
| --- | --- | --- |
| H0 | 普通领域适配后仍存在有意义的执行缺口 | 同数据、相同曝光/计算下G-only SFT和强轨迹渲染足以解决时，停止增加复杂机制 |
| H1 | 模型读取实际历史和空间实例 | 完整前缀、末帧、相关事件遮蔽、无关等面积遮蔽、同末帧换序；比较观测历史，不能强求下一步不同 |
| H2（核心） | 事件状态与空间条件改善可见生成执行 | 正确/预测/打乱状态、仅顺序文字、无序实例集合、几何控制基线和相同参数的通用adapter |
| H3 | 共享理解生成产生额外收益 | 同底座共享与独立任务adapter、分离U+同G、同监督和样本曝光/总计算两套配额 |
| H4（可选） | 实际RGB反馈超过计划反馈和额外采样 | 每次调用、总NFE/延迟、重试数受控；在线与离线回滚分开 |
| H5 | 收益超出训练模板和单字条件 | 未见微调字符、书写者/字体家族、独立渲染器，多字与授权真实域分层 |

H2是首要方法证据。H3未成立时可以保留事件执行方法，但不得称共享协同成功。H2未成立且简单方案已满足目标时，停止扩展或缩小研究对象。H1提高而生成未改善，仅支持过程理解结果。

## 5. 首篇范围和交付

主域为固定画布、无手遮挡、轮廓可辨、规范明确的风格化单字。目标是从空白自由生成完整RGB过程，同时保持最终字形及参考风格；P续写为关键分析任务。真实手笔、连笔行草、交互擦写、多字长视频不作为首个阶段的必需条件。

核心交付为方法实现、可用检查点、同协议适配强基线、原始输出与独立事件评分、机制干预与泛化分析。数据和评价不替代生成成果；没有训练结果时不发布模型性能排行榜。

## 6. 按证据推进的阶段

| 阶段 | 实验 | 交付与决策 |
| --- | --- | --- |
| P0 任务/数据/接口 | ENV-01、DATA-01、EVAL-01 | ENV-01三接口、最小部分参数反传/更新及独立重载已通过；DATA-01许可/候选数据/分组与EVAL-01冻结受控自动门槛已完成；人审和独立来源划分待办，两项blocked，完整P0未验收 |
| P1 查明瓶颈 | SO-00、BASE-01、EVAL-02、SO-01 | 先检查采样/codec，再对原生输出人工归错；校准实际生成域评分；定位历史或执行失配 |
| P2 排除简单解 | FIT-01、ADAPT-01、SO-02 | 小集过拟合、同数据普通SFT、轨迹+风格渲染、文本/空间条件；建立可改进上界 |
| P3 核心机制 | SO-03A、SO-03B、CAUSAL-01、SO-03C | 最小联合基线→事件约束→干预→共享归因；新增模块一次只变一个 |
| P4 可选反馈 | REC-01 | 实际RGB读回、等成本重试、在线失败/离线回滚；不阻塞P5主生成结果 |
| P5 正式验证 | SO-04 | 冻结后测T完整生成、独立P续写、分布外、人工盲评与CI；按证据缩小主张 |

执行门槛详见[实验矩阵](experiments.md)。环境、数据、观察器和算法可以并行做不相互依赖的工作；不安排无设备支持的训练承诺，也不预报完成时间。

## 7. 当前候选实现与最小第一轮

Lance_3B_Video仍为主视频UMM候选。首轮保持同一预训练底座和冻结codec，通过后训练验证概念。LoRA/小adapter优先仅在实际实现支持时采用；事件空间接口和多帧前缀并非已获官方保证，必须检查。生成端使用扩散或flow与UMM定位兼容。

第一轮先做16字接口/数据排错，再用开发字形成错误分布：同一视频底座的原生提示、普通SFT、正确顺序提示、空间控制，以及规则/轨迹渲染。若这些对照未显示明确剩余问题，暂不训练复杂事件模块。

本轮已构建64观察器开发字＋64独立保留字及512个主学习字（320/64/128），共2,752段受控RGB，见[DATA-01/EVAL-01报告](p0_data_eval_report_2026-10-28.md)。固定源revision与许可已记录，人工规范/RGB核验为0，独立字体/书写者/记录划分缺少素材；不能当作已审定正式基准。后续规模化GPU预算仍未配置。
