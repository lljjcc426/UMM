## 2. 实现顺序与待编写模块

| 模块 | 最小交付 | 关键单元测试 |
| --- | --- | --- |
| manifest/adapter | 合法split、文字/风格、prefix帧、监督目标的parquet映射 | future/evaluation_only不得进入推理；timestamps严格排序；同group不跨split |
| 独立观察器 | ROI/墨迹/几何身份/时间三态，双人标注对齐 | 换序、逆向、同帧未知、漏笔/消失、空输出；模板外不能强判 |
| U/G单任务 | 官方接口→16条拟合→重载一致性 | labels mask、pad与loss归一、梯度非零、codec输入输出 |
| M0混合SFT | 文本状态CE+视频loss，冻结codec | 可训参数名单与两类batch梯度，预算/曝光日志 |
| M1事件adapter | JSON起步→空间query，位置/身份/进度 | 序列化argmax断梯度如实记录；soft路径的梯度实际检查 |
| M2执行监督 | 可微新增/保持/事件头，单项开关 | loss与最终硬评分分离；观察头监督可靠；匹配失败masked并报比例 |
| 自由rollout | 固定窗口，真实输出读回，完整视频存档 | 不读取真值边界或未来帧；过去片段冻结/拼接规则对各方法一致 |

上表是待开发清单，本次仓库只提供设计、结构登记与校验代码；没有伪装成可运行训练实现。

## 3. 前缀与共享接口的两个现实检查

若底座仅支持最后帧I2V，完整prefix先由U读入，G接最后帧和结构状态；这条信息路径须明确。若新增多帧prefix adapter，则分离基线也获得同adapter。不能假设原生接口已支持任意长度前缀冻结。

自回归/片段生成将已输出片段固定，是工程保证；新方法必须在相同冻结策略的baseline上比较。跨片段VAE边界可能引入缝隙，检查短笔跨chunk的连续性。真值事件起止不可免费用于运行时分段；长度控制token、预设时长和停止规则要公平提供。

## 4. 训练配方与预算

不从零预训。先保持codec和底座固定做普通领域SFT，再按实现可用性选择PEFT。建议先在开发集以少数学习率和loss权重进行小规模搜索，记录所有尝试；未有硬件前不填一个看似准确的显存或天数。不同候选拥有相同调参预算，不能只精调主方法。

数据量、视频分辨率/fps/窗口、采样步数、batch/累积、precision、冻结参数、loss权重、seed、教师/渲染成本和checkpoint选择全部进入运行记录。推理要求同分辨率/有效帧/总NFE对照，同时给native能力表；原生设置无法完全匹配时明确差异。

ENV-01后填写GPU型号/数量、单位步/视频时间、峰值显存、剩余GPU小时、媒体存储和人工标注预算。预算null禁止把大规模任务登记ready。仅CPU阶段可完成数据规范、校准标注、结构测试，不承诺GPU性能。

正式核心至少3训练seed为初始目标；预算不足可先一个seed做探索，不能将多个推理seed冒充训练重复。总成本包含理解、视频、观察、重试、预处理和外部调用。

## 5. 科学完成与工程完成分开

计划验证通过仅检查结构及局部路径。数据取得、评分器跨域校准、模型接口跑通、算法实现、正式对照结果五项分别验收。每个完成状态必须有run记录和结果制品；没有实际GPU运行时，任何性能字段保持null。
