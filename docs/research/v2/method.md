# v2：事件理解与可见执行的方法设计

2026-10-27；候选方法，未实现或验证。[总目标](README.md) · [实验](experiments.md)。

## 1. 任务及信息契约

| 协议 | 推理时可见信息 | 输出及用途 |
| --- | --- | --- |
| T（主任务） | 字串c、地区/书体规范n、独立风格参考r，初始空白画布 | 从空白自由滚动得到完整RGB视频；所有早期错误保留计分 |
| P（机制诊断） | T条件加截止t的实际RGB前缀 | 忠实描述已发生状态并续写；分别评前缀合法性和后缀执行 |
| O（特权上界） | 额外真实笔画几何、真实状态或进度 | 判定执行瓶颈，仅与同特权信息方法比较 |
| I（可选独立任务） | 完整目标艺术字图 | 图像到过程；不把该图移入T/P输入 |

每个协议再标`G0`或`G1`：G0提供文字规范/笔画类别规则；G1额外开放同版本标准字库几何模板。G1模板不是该样本风格化目标真值，但确实增加空间信息，所有可比方法同权访问。公开标准字库可包含微调未见字，必须披露；此时评的是未见字上的适配/泛化，不能称完全无字库知识。

目标字最终图、逐帧真值掩码、实际事件边界和渲染日志均为`evaluation_only`或训练监督；T推理不能读取。独立风格参考不含该测试样本终图。训练可用完整target计算loss，理解端输入及attention只见合法前缀；禁止把未来target特征经共享缓存送入U。

主推理窗口使用运行前固定的原生帧长度及上下文上限，不按真值笔画边界切段。窗口可跨笔，也可能一笔跨多个窗口。真值边界分块只作O上界；预测事件触发分块需与等总计算固定窗口比较。

## 2. 四个必须分开的表示

- `normative_program`：规范中的实例及允许先后约束。
- `planned_events`：模型准备执行的实例、位置、方向和进度。
- `observed_events`：从实际RGB看见的身份、时间和完成状态，允许错误/未知。
- `evaluation_events`：独立评分器与人工复核得到的记录。

实例ID不能由预测出现顺序命名。以“三”为例，ID绑定上/中/下三条几何实例；全是横这一类型标签不能识别交换。规范序和实际序不得相互覆盖。

状态s_t包含已观察序列、完成集合、活动实例、进度区间、可见性和首错；规划状态p_t包含下一目标实例及拟定几何。主方法采用:

`q_t, observed_state = U_theta(c, r, n, RGB_prefix)`

`planned_event = P_theta(q_t, normative_program)`

`next_chunk = G_theta(RGB_prefix, q_t, planned_event, r)`

生成后从真正输出像素重新估计状态。完整生成从空白起每步只用自生成前缀；teacher-forced单步表现不能代替自由滚动成绩。若规范实例与状态都确定，下一合法事件可由规则求解；规则选择相同地提供给基线，不把查表包装为推理贡献。

## 3. M0：必须击败的简单方案

先实现同底座G-only领域SFT；另做U-only、CE状态+视频FM/MSE的混合联合训练，以及短JSON状态接原条件的版本。两类任务共享参数可共同接受梯度，但采样/argmax生成的字符串本身无可微梯度通路。

对照还包括：文本正确笔顺提示、同信息轨迹生成+风格化渲染、视频模型空间条件、标准模板硬渲染，以及当前笔mask硬合成。各方法均提供相同领域训练数据与规范；零样本只作背景。

如果普通SFT或结构化渲染在所需外观/过程/成本上已满足目标，则H0未成立，应停止额外结构或重新界定真正未满足的需求。不能只挑弱零样本模型突出新方法。

## 4. M1：候选核心——空间可定位的事件条件

仅当开发集证据显示实例混淆/执行失配时，在UMM中加入小型事件接口。每个query表示一个具体笔实例，包含规范身份、预测空间位置/区域、已完成/活动状态、笔内进度与不确定度；局部细节仍由生成器建模。

理解端从RGB前缀估计这些量。T-G0中的未写几何由模型预测；T-G1可使用统一开放的标准模板并学习风格对应；O才给目标真值几何。事件query通过适配层进入视频生成条件，token位置与视频时间分开编码。模型生成的RGB仍需独立验证，提供事件条件不构成正确性证明。

必须比较：同token数普通latent adapter、仅笔型/计数、无序实例集合、文本JSON、有序空间事件。训练时分别关闭U梯度到事件接口、关闭事件条件、使用独立任务adapter。仅参数共享或注意力可视化不足以证明跨任务正迁移。

## 5. M2：对实际可见变化施加监督

基础目标：`L_base = L_video + lambda_state L_state`。L_state监督真实观察序、空间身份与完成区间，不能把坏历史自动改写为规范。

根据失败再单独尝试：

| 项 | 监督对象 | 必须检查 |
| --- | --- | --- |
| L_event | 在预测干净视频或其特征上，对各实例的增长/活动区间进行可微监督 | 索引按输出实际时间；从视频loss到adapter/共享参数的梯度真实存在 |
| L_new | 当前目标实例的可见新增墨迹与非目标提前新增 | 在适用墨迹层上计算；透明、晕染、阴影不直接按灰度单调假设 |
| L_keep | 已完成结构、位置与身份保持 | 结构保持允许合法纹理变化；硬复制过去帧的保障归于执行器 |
| L_pair（可选） | 控制几何/终态/时长的正确与错序过程表征 | 先监督实际历史辨认，未证明它单独能改善自由生成 |

硬阈值分割、匈牙利匹配、argmax序列检查用于评价，不能直接当可反传loss。可微训练观察头须有独立真值监督和冻结/解冻消融；最终评价不用该头作唯一裁判，以防共适应。

若加入序约束，可用可微进度估计pi_i(t)，只在可靠可见时间上约束前笔完成与后笔开始；训练噪声步、视频物理时间和实例编号分别定义。速度可以变化，不能为了对齐到唯一匀速模板惩罚所有合法书写。

## 6. 机制干预与因果证据

固定文字、风格、底座、seed和有效信息，分别替换事件身份、完成状态、空间锚点与活动进度，观察生成的受影响区域和下一事件。遮蔽相关历史与等面积无关区域作对照；干预应产生预先指定的局部变化，同时检查是否破坏旧墨迹。

正反两类干预都需要：正确状态帮助失败样本；错误状态使对应执行按预期偏离或被模型拒绝。若模型忽略状态仍获相同效果，不能把收益归为事件条件。分布外错乱状态仅作压力测试，主要归因使用与真实误差相符的扰动。

同末帧换序证明终态不足以识别历史，但某些干净累积前缀的完成集合可由末帧充分推断；两条历史也可能拥有相同下一合法动作。不得人为要求所有前缀都需要完整历史或输出不同下一笔。

## 7. 生成历史训练与可选恢复

先用正确前缀建立能力，再使用训练/开发字上的模型rollout。理解标注描述实际发生的事件；视频target只使用可合法继续的配对或明确的离线回滚目标。已犯不可撤销顺序错的在线前缀，监督停止/报告错误，不将未来添墨标成修复原历史。

REC-01在核心方法后单列。比较计划日志、实际RGB、独立外部观察器、oracle状态及等预算随机重试；同时记录首次成功、最终成功、重试/拒绝和成本。自检分数不能成为唯一训练奖励或评判依据。RL仅在监督学习已稳定且奖励独立校准后作为后续选项。

## 8. 成功之后能主张什么

H2成立支持事件条件提升实际执行；H3另成立才支持共享训练额外价值；H4另成立才支持反馈恢复。字形和风格必须满足预先确定的非劣要求，不能用粗糙、低帧率或丢难例换取顺序分数。最终报告完整T自由生成；O/P结果解释机制，不能替代生成主结果。
