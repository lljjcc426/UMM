# 任务定义、最近前作与候选方法

协议 stroke-video-v1；2026-10-26；状态：研究设计，机制和收益尚待验证。

## 1. 三个任务，禁止混用输入优势

| 协议 | 模型可见输入 | 输出与评价 |
| --- | --- | --- |
| T：文本条件从空白生成 | 目标字串、规范版本、独立风格参考；参考不得含该样本最终目标图 | RGB完整书写视频；全历史严格过程与字形 |
| P：实际前缀续写 | T的条件及截止t的真实/已生成RGB前缀 | 观测状态、后续短片段；前缀合规性和后缀执行分别评 |
| O：oracle控制执行 | 额外提供真实实例掩码/轨迹/进度或事件状态 | 执行上界；与同样获得这些控制的基线比较，独立于T/P排名 |

已给最终艺术字图的image-to-process任务可另设I协议。不能把I的目标图作为T的免费输入。所有协议中，规范字典若提供给主模型，也应同样提供给可比基线。指定规范、真实人类记录顺序和可接受行草变体分别存储。

初始任务为固定画布、单字、无手遮挡、可辨笔画结构。没有真实笔尖/同步传感时，只承诺观察可见墨迹事件；接触压力和物理抬笔保留为N/A。

## 2. 状态、动作和实际执行

目标字c、风格r、规范G、真实前缀V≤t。观测状态s包含：空间实例ID、已完成集合、实际发生序列、活动实例及进度区间、未知项、首错位置、历史是否已违规。规划动作a包含下一实例、几何/方向约束与允许的停止/回滚动作。

模型分解为：

`observed_state = Uθ(c, r, G, RGB_prefix)`

`next_action = Pθ(observed_state, G)`

`next_RGB_chunk = Gθ(RGB_prefix, observed_state, next_action, r)`

U/P/G可以共享部分参数；同一程序调用三个模块不等于已经验证共享学习。生成后重新读实际RGB，不用规划日志覆盖观察结果。

必须区分 `observed_order`、`normative_order` 和 `planned_order`。错误前缀的观察标签忠实记录错误；规范下一动作的规则不得伪装成已观察历史。笔画ID通过空间位置/轮廓绑定，“三”的三横不能共用一个类型ID。

### 同终态反例的作用边界

同一最终图像可由不同事件次序得到，末帧函数无法普遍确定实际历史。此反例支持时序监督的必要性，不证明UMM或特定算法必需。若两段历史产生同一合法后续状态，下一笔可以相同；应在顺序/首错判断上检验差异，不人为要求不同动作。

真实错误历史是不可撤销事实。在线续写只能报告/停止或按明确容错任务继续；离线编辑可回滚未发布片段，需保留首次失败、回滚次数及最终成片。两协议不能合成一个成功率。

## 4. 候选方法：逐步增加最小机制

### M0：最小联合基线

复用可运行的视频UMM，混合 `prefix→observed_state`、`state/condition→video`，使用已有文字CE和视觉flow/扩散损失。共享范围按参数名称记录；先冻结视觉codec，避免同时改变可观测上限。状态先用短JSON序列，不生成长篇解释。

`L0 = L_state_CE + λg L_video`

M0也是必须击败的基线。JSON经过采样/argmax后不可微：两任务可以通过共享参数共同训练，但不能声称梯度穿过离散字符串。训练用真实状态而推理用预测状态时，需测并报告exposure gap。

### M1：有空间身份的事件条件（待验证新增）

仅当P1/P2确认重复同类笔、短笔或交叉导致状态—执行失配时，增加少量事件query/adapter。事件向量编码实例空间位置、已完成/活动状态、进度与置信，不只编码笔形类别。共享观测表示进入视频生成条件；外部几何模板、预测几何和oracle几何分协议。

首次实现可把事件状态序列化给已有条件接口；如果原生接口忽略它，再训练轻量空间条件模块。真正跨分支可微的soft query路径必须检查计算图，记录哪些参数接受两个损失的梯度。

### M2：依据失败添加局部执行约束

固定画布下，可在适用样本加入当前笔区域的新墨迹监督 `L_new` 和已完成区域的结构保持 `L_keep`。每项独立消融，单独报告权重和显存/计算。阴影、纸张运动、墨晕或未完成模糊区不能直接套像素单调条件。硬阈值观察器只作评价；未经可微替代与校准，不将其分数写成能反传的loss。

`L = L0 + λnew L_new + λkeep L_keep`

第一轮不加RL、复杂奖励融合或新的大规模预训练；否则难以定位收益来源。

### M3：真实输出读回

从训练/开发字上的自由生成采集失败前缀；以真实观察状态监督U，以经验证的正确后续监督G。比较计划状态、自身RGB读回、外部独立读回和oracle状态。自评一致可能只是两端共享同一错误，最终评测使用独立人工/观察器。

## 5. 必做归因与反证

- 状态信息：none / oracle / predicted / shuffled；反例要控制字形、时长、总墨迹和显著性。
- 结构监督：有序空间实例 / 无序笔画集合 / 只有笔型计数；同等文本长度与训练曝光尽量匹配。
- 共享：生成only / 独立任务adapter / 分离U+G / 联合共享；同时报告驻留、可训、活跃参数，不能只比名义模型大小。
- 条件使用：遮蔽相关历史与遮蔽同面积无关区域；随诊断变化的执行是否符合预注册预测。
- 反馈：固定重试数和总采样成本；禁用反馈是否消除收益；若确定性渲染保证顺序，归因于执行器。

机制指标（特征相似度、注意力、梯度夹角）作为诊断，不能单独证明共享正迁移。最终须由实际RGB过程、字形与泛化结果支持，且允许负结果改变研究路线。
