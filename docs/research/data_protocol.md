## 1. 数据准入分层

| 来源 | 可用于什么 | 本项目准入前必须核对 |
| --- | --- | --- |
| Make Me a Hanzi / Hanzi Writer / AnimCJK | 有序轮廓/中心线、规范合成、规则渲染强基线 | 源文件revision、地区/繁简/笔顺逐字审核、字体/图形与代码各自许可；不把median当真人速度/压力 |
| CASIA-OLHWDB | 真实在线字/行轨迹、书写者风格 | 具体版本、文件字段、获取许可、writer split；实际顺序与指定规范分别标，不能补造逐点时间戳 |
| OpenHandWrite | 经核实字段的真实时间/笔压对照 | 数据卡、采集字段/单位与使用条件；取得样本后再决定适用任务，见[资源卡R07](../reviews/R07.md) |
| 9523字逐笔掩码等派生资源 | 静态实例/规范顺序辅助 | 追溯原SVG/CCSE来源与许可，检查是否只提供逐笔整幅mask；整笔显示不等连续笔内运动 |
| CHTR / BCSS | 带宽度轨迹或静态笔画结构辅助 | 已公开数据内容与论文规模不同；下载状态/真实时间缺失必须保留，见[L186](../reviews/L186.md)、[L184](../reviews/L184.md) |
| AWCV等空中书写RGB | 真实手指运动的辅助/OOD诊断 | 无纸面落墨，不能作为纸上逐笔添墨主集；类别/动作标注与版权另核 |
| 授权真实纸面录像 | 真实视觉分布的最终评测 | 同意/匿名化、完整帧率、规范和逐笔时间标注；有同步数字笔/手势才评真实接触/压力 |

初始只用可证明有权使用的规范源或自行制作的简单几何模板。未完成授权的资源标记 `license_pending`，不得进入可发布训练包。公开视频存在不代表允许下载训练或二次分发。

## 2. 计划规模与划分

校准集：64个经人工核规范的字符，覆盖重复同类、交叉、包围、折笔和短点；用于观察器阈值、人工说明和失效测试，不进入最终模型测试。

主学习集建议512字：320训练、64验证、128测试；与校准字不重合。数据源不满足覆盖/授权时缩减并发布实际清单，不虚报512。每字的风格、速度、纹理版本数量依据P0吞吐和质量决定，清单未创建前不计算总视频数量。

两条独立泛化轴：

1. **字符OOD**：测试字未出现在本项目微调训练字集合中；不能据此断言底座预训练未见该Unicode字符。
2. **风格/域OOD**：使用已见字符但未见字体家族、writer或渲染器；再测字和风格同时OOD。不同轴分表，不让同时变化掩盖失败原因。

同一个字符模板的颜色/缩放/速度/相同真实来源变体必须随其组划分。字体家族而非单个字体文件名作为分组依据；书写者与原作品分组去重。训练监督中给出的风格参考优先选同风格的其他字，目标字参考单列I协议。

## 3. 合成过程和负例

对每个已审核序列建立连续轨迹或沿路径揭示的渲染过程。真实采样时间缺失时明确 `timing_origin=synthetic`，按弧长/速度模型重采样；压力代理标 `pressure_origin=proxy`。不要把累计mask一帧出现整笔的数据称为包含真实笔内时序。

保持最终像素、字形、时长与总笔数相同构造换序/逆向对；漏笔、重复、拆并、整字闪现、墨迹消失、同帧多笔另设错误类。单笔字不做笔间换序；缺笔与重复负例不能声称同终态不变。保留样本适用性和构造失败，不为了凑固定数量复制数据。

这些负例首先用于评价校准和过程理解。生成学习的目标优先采用合法轨迹与经审核的修复目标，不能把非法视频直接混作规范生成的正样本。

## 4. 每条样本必需字段

`sample_id / character_text / locale / script / norm_id / source_uri / source_revision / license_status / source_group_id / writer_id / font_family_id / renderer_id / split / pair_group_id / timing_origin / pressure_origin / media_sha256 / native_fps / frame_timestamps / resolution / crop_transform / stroke_instances / allowed_orders / observed_events / visibility / annotation_provenance`。

每笔实例保存稳定几何ID、轮廓或中心线引用、方向定义、允许的开始/结束关系。事件保存开始/结束的时间区间、活动进度、可见性和置信；无信息写null，不用规范序列填充观测空缺。标准图和未来帧仅供离线标注/评价的字段放到 `evaluation_only` 区，不得由训练适配器读入在线前缀输入。

## 5. 数据质量关口

规范、几何实例、事件时间和像素执行分别审核。保存字符集合与文件hash、源分组重复检查、合法序列有效性、真实帧时间单调性、零帧/损坏文件和全量尝试覆盖。只用source hash抓不到渲染变体，需结合源ID、字体/作者及近重复检查。

至少双人独立标注校准子集，记录分歧和最终仲裁；人工不能只看最后一帧。自动评分器训练/校准字符与正式测试字符隔离，真实录像单列外部测试；测试集的错误类型、阈值与模型选择在看最终结果前冻结。

## 6. 数据产物与目录

大媒体存受控外部存储，Git只存许可说明、manifest、checksum、split、schema与小型自制示例。建议运行产物：`runs/<run_id>/manifest.jsonl`、`predictions.jsonl`、`events.jsonl`、`metrics.json`、`failures.jsonl`、`run.json`。当前这些是待生成路径，不代表文件已经存在。

正式测试必须列出预计样本数、成功输出数、不可判定数、无输出数及各原因。不得通过评测脚本只枚举已有视频把失败样本排除。
