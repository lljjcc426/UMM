# 指定目标与完成判断：开发集控制

首轮视觉适配后，多线条中指定目标缺失的6题，存在判断只对1题。本组控制用于区分目标选择、提示表达和参考比较的问题，不增加训练，不使用视觉测试集。

固定 `checkpoints/h1_visual_state_lora_v1/adapter.pt`，使用原开发集的平行横线、平行竖线和交叉三组，共12个状态案例。每个条件包含存在/完成两类问题及两种问法，共48题。

| 条件 | 图像 | 提示 | 比较用途 |
|---|---|---|---|
| original | 原始参考＋当前 | 原提示 | 从上一轮完整预测中取出相同案例，不重新推理 |
| prompt_only | 原始图像 | 加入蓝框解释 | 与original比较提示本身的影响 |
| target_boxes | 在参考及当前的目标范围加蓝框，其他线条保留 | 与prompt_only完全相同 | 与prompt_only比较位置标记的影响 |
| target_only | 参考和当前均只保留已知目标笔迹，位置、比例、线宽、进度不变 | 与original完全相同 | 与original比较已给定实例后的状态判断 |

蓝框由完整参考中指定目标的边界向外扩12像素得到，与当前是否出现、完成多少无关；上下框相差216像素。框线为蓝色，问题明确只判断黑色目标笔迹。交叉线可穿过框内，因此蓝框提供范围，不能保证消除所有干扰；边框也可能覆盖其他线条的少量像素。位置提示未出现在此前训练中，失败不能单独证明模型没有空间能力。

`target_only`使用生成数据的实例标注删除其他笔迹，这是外部提供的正确实例对应，**不能把这个条件的成绩计为自主定位或两项门槛通过**。它能检验目标选择负担降低后，完成比较是否仍有错误。

三种新条件均完整运行，不根据中途成绩选条件或案例。全部来自已用于诊断的开发集，只有3个几何组；分组区间仅用于本组探索，不代表独立泛化。单笔、汉字、字体及时间顺序不在此次控制中。原130个视觉测试案例继续留出。

构建：`python scripts/h1_target_controls.py build`。每个条件的`inputs.jsonl`与`labels.jsonl`分开保存；未改变的图像通过相对路径复用。原始案例和蓝框坐标保存在根目录的`cases.json`与`build.json`。模型执行仍使用`h1_run_showo.py --view reference_current --format json --constrain-answers`；评价使用`python scripts/h1_target_controls.py analyze`。

另用 `python scripts/h1_target_controls.py build-training-subset` 取出此前视觉训练中三个多线条布局各自的第一个几何组，保留全部4种进度、两类任务和两种问法，共12个见过的案例、48题。运行及评分明确使用 `--split train`。这项检查用于辨别训练内拟合是否仍有错误，不能作为开发成绩或泛化证据。

`build-all-target-queries`在同样12张开发图上询问全部目标，共28个“图像＋目标”案例、112题；没有新增独立图像。原目标的48个问题与原模型输入完全相同，基线复用已有预测并保留来源；其余64题另行运行原视觉适配模型。继续训练后的模型完整运行112题。除了逐题分数，还统计同一图中真值不同的两个目标是否都答对，用于检验模型能否随指定目标改变回答；这些目标配对仍依附于原来的3个几何组。

补充评价中，原问题以外的目标在各自几何组内状态固定；该设计用于暴露同图目标切换失败，不能单独排除目标名称先验或证明泛化。完整结果见[控制与追加监督报告](../../../results/h1/showo2_video_1_5b/target_controls_v1/README.md)。
