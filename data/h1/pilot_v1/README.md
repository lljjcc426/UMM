# H1 首轮受控诊断数据

版本 `pilot_v1`，2026-10-16。用于诊断冻结VLM对实际书写过程的读取、判断和下一动作选择。数据由本仓库脚本绘制，不含外部字库或真实书写视频。

## 范围

12个过程案例，涉及“三”和“十”，包含空白、半笔、完整前缀、正确整字、换序、提前换笔和反向运笔。每一笔按四分之一长度递增，画面224×224，黑线白底，固定视角，无手部。只存在指定笔画实例，笔迹累积，不擦除、隐形重描或添加其他笔。

33个模型输入来自四种条件：

| 条件 | 数量 | 提供的信息 |
|---|---:|---|
| `sampled_frames` | 12 | 完整目标参考图＋从空白开始的全部离散进度帧 |
| `last_frame` | 11 | 参考图＋过程末帧 |
| `endpoints` | 5 | 参考图＋空白首帧＋末帧 |
| `oracle_state` | 5 | 准确的文字观测状态，无图片；只评价判断和动作 |

这些条件并未覆盖完全相同的案例集合，不能直接把四组平均分当作配对提升。配对分析应使用相同`case_id`。多个输入共享一个源案例，33个输入不等于33个独立书写样本。

模型得到目标字、笔画ID含义、指定规范和动作策略。测试关注它能否如实读取实际过程，不评价规范笔顺记忆。参考图始终位于第一张并明确标为非时序输入。输入文件仅含不透明案例编号；构造类型和真值放在独立文件中，推理脚本不读取标签。

## 标注与可观察性

| 层次 | 字段 | 含义 |
|---|---|---|
| 观察 | `seen` | 末帧可见的笔画实例集合 |
| 观察 | `finished`, `unfinished` | 相对完整参考，哪些笔完成、哪些只有部分 |
| 观察 | `order` | 实际开始出现的顺序；无法恢复为`null` |
| 观察 | `directions` | 各笔实际方向：`forward`、`reverse`或`unknown` |
| 观察 | `early_switch` | 提前换笔时新笔的出现序号；无此现象为`null`；不确定为`unknown` |
| 判断 | `status` | 已观察前缀满足指定规则为`valid`，已确认违反为`invalid`，证据不足为`unknown` |
| 判断 | `first_error`, `error_type` | 首次违规的出现序号及类型；分别保留无错与不确定 |
| 动作 | `next`, `target` | 下一动作及目标笔画，不实际执行或生成 |

顺序序号从1计。`seen`等集合字段忽略排列；`order`严格区分排列。`null`、`unknown`、缺失字段分别处理。

静态图不能提供运动方向；多笔终态一般不能恢复实际先后。只有一个可见实例时，实例顺序可确定，也可排除跨实例提前换笔；方向仍不确定。部分静态状态能排除所有合法历史：上横与下横出现但中横缺失，违反指定顺序；上横只写一半而中横完整，则无论实际先后如何都存在违规，但无法单凭末帧确定首错位置和类型。这些结论依赖本数据的累积、无擦除等约束，不能直接用于任意真实视频。

动作采用预先指定的保守策略：已确认违规→`stop_error`；历史或方向证据不足→`need_more_frames`；合法半笔→`continue`；合法完整前缀→`start`下一笔；合法整字→`done`。动作分数衡量遵守此策略的能力，不代表唯一合理的真实控制策略。当前数据未包含回补、局部修复或继续写完错误字的策略。

## 文件与复现

- `inputs.jsonl`：实际送入模型的提示和有序图片路径。
- `labels.jsonl`：期望输出及评分范围。
- `source_cases.json`：构造事件、案例类型和帧数。
- `images/`：参考图及过程帧。
- `preview.png`：五个案例的简略展示；评测使用原始帧，不使用此拼图。

构造脚本：[h1_dataset.py](../../../scripts/h1_dataset.py)。在仓库根目录运行：

```bash
python scripts/h1_dataset.py
```

模型运行开始后，不在本版本上修改提示或标签来适配结果。后续扩展使用新版本。当前全部为诊断集，无训练集；只有两个字和一种渲染方式，不能用于估计真实视频、字体或未见字的泛化能力。
