# CPU 方法可行性执行报告 · 2026-11-04

## 运行范围

研究方案：原始字形图像 `I` 与五类有序笔画描述 `D` 成对；视觉与文本分支分别编码；通过可选择的融合机制学习联合表示；候选最终输出模型生成的受约束绘制程序，由 CPU 代码生成 MP4。

本轮已按此目标实现**隔离 CPU 概念验证**。仓库中 S2 预训练前四模型的36请求尚未在本轮实际执行。原 S0–S2 文件没有被修改。

## 实际结果

- 配对数据：生成2条 **synthetic fixture**；两者均含3笔、五类序列相同、结果字不同。读取器检查 opaque ID、目录约束、图像实际有字、许可/金标字段未进入训练导出、跨分区组泄漏。
- 融合接口：`sft/global/cross/ordered` 各一遍随机参数的 CPU 前向与反向，2张随机 RGB、目标长度4；序列因果右移、字符通路与局部 Cross-Attention 输入均有测试。**优化器 step 0，预训练权重0，模型能力成绩0项。**
- 绘制程序：3个实际 CPU MP4（`土`、`士`、`土`同轮廓换序），每段52帧、256×256、24 fps，视频可解码，首帧空白，终帧有墨迹，阈值检测墨迹消失像素0。`FFmpeg/libx264` 实际调用成功。
- 顺序不可识别性对照：`土`正确程序与同三条笔画几何的不同执行顺序，首帧和未编码终帧 RGB 完全相同，粗笔型序列同为(横、竖、横)，早期过程帧不同。编码后终帧像素略有编码差异，二值墨迹完全一致。验证了**终态＋粗笔型序列不总能确定实际实例顺序**这一构造反例。
- 实施中发现并修复了路径逐帧重绘造成少量墨迹像素消失的错误；改为累计墨迹并复测成功。
- `13` 项单元测试通过。无训练、GPU/MPS、模型权重下载、付费服务、GitHub写入。

## 能证明什么

- 数据格式和信息权限有可执行验证工具；核心思路可映射到模型模块的张量接口。
- 受约束代码生成路线可以以很小CPU成本生成简单白底笔画动画。
- 原始配对在重复同型笔画实例顺序上存在可检验的不可辨识情况，提醒评测时不要用E2代替E3/E4/G2。

## 当前还没有证明什么

- **尚未训练、运行任何 UMM/VLM**，没有验证模型学会了笔画顺序/位置/方向，也没有证明Ordered Queries超过普通SFT/XMP式双向融合。
- `fusion.py` 是随机初始化的简化模块，与真实Qwen/InternVL-U权重及输入processor没有对接；没有 `masked visual` / 真正 bidirectional attention 或绘制程序输出的神经decoder。
- 演示绘制程序由CPU固定fixture提供，没有经过模型生成；所以仅属于G0式执行器测试，绝对不算G2生成结果。
- 单一线条宽度、合成2字、256px画布，不能外推至真实书法视频、美术品质、复杂折钩/笔锋或未见字体。没有正式测试集金标或跨模型泛化结果。

## 下一阶段的可检验门槛

1. 确认 S2 四模型真实视觉接口通过正控后，完成训练前理解能力的独立诊断；若未批准 GPU，先补CPU只读对照和程序评价测试。
2. 根据真实单卡内存与训练接口选择一个主底座，以同等训练预算先跑 M0→M1（普通 Image→D SFT）→B/C 结构，再考虑增加局部对齐与实例监督。
3. 代码程序输出要分 G0 Oracle、G1 geometry-assisted、G2 Image→Code，并在 G2 下严格排除规范目标模板泄漏；统一执行器，原始失败全计。
4. 独立字形来源/正式保留集建立后才能报告跨域和跨模型泛化。现有开发集只有单一Arphic来源，逐笔强资格覆盖36字/130笔，正式保留集0。
