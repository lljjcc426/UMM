# UMM 扩展文献矩阵

与[首批核心文献矩阵](文献矩阵.md)配合阅读。本文按问题组织后续扩展，不设文献数量上限。标题和版本以原始论文为准；综述仓库仅作为发现入口。表中的“结果”是论文报告，不代表本次独立复现。

证据标记：**正文**＝本次查看过与所列结论有关的方法、实验或消融正文；**摘要**＝核对原始摘要，尚未据此开展实验细节评价。保存了全文但没有检查相关实验的条目仍标为“摘要”。外围生成模型、数据集和应用论文明确说明关联，不等同于核心 UMM。

## 1. 早期形成：图像如何成为语言模型能够读写的内容

| 文献 | 研究问题与方法 | 得到什么、怎样理解 | 证据 |
|---|---|---|---|
| [OFA，2022](https://arxiv.org/abs/2202.03052) | 将生成、定位、描述、分类及语言任务统一为带指令的 seq2seq | 早于当前大语言模型式 UMM 的任务/模态统一路线；不需要下游任务专用层 | 摘要 |
| [Unified-IO，2022](https://arxiv.org/abs/2206.08916) | 把图像、像素图、框和语言统一为离散输出词表，联合训练 90 余数据集 | 将经典视觉任务与语言任务置于同一模型；是 Unified-IO 2 的前序 | 摘要 |
| [Versatile Diffusion，2022](https://arxiv.org/abs/2211.08332) | 共享/可交换层组成多流扩散网络，统一文生图、图生文与变化生成 | 表明多模态统一并非只源自 LLM；任务接口和模块共享已经是早期问题 | 摘要 |
| [UniDiffuser，2023](https://arxiv.org/abs/2303.06555) | 每种模态使用独立噪声时间，同一 Transformer 预测各模态噪声 | 通过不同时间组合学习边缘、条件和联合分布；是连续多模态扩散的重要前序 | 摘要 |
| [Emu，2023](https://arxiv.org/abs/2307.05222) | 将交错图文/视频转为序列；预测离散文本 token，同时回归连续视觉 embedding | 让同一序列模型具备图文输入输出与上下文学习；统一序列并不要求所有模态使用相同数值表示 | 摘要 |
| [SEED，2023](https://arxiv.org/abs/2307.08041) | 视觉 token 引入一维因果依赖和高层语义，兼顾判别与重建 | 用有限适配让 LLM 能看和画；tokenizer 的顺序和语义粒度成为核心设计变量 | 摘要 |
| [LaVIT，2023](https://arxiv.org/abs/2309.04669) | 动态离散视觉 token，按图像内容改变序列长度 | 统一理解与生成，同时研究视觉序列冗余；不能只看 token 数而忽略编码器和解码器成本 | 摘要 |
| [NExT-GPT，2023](https://arxiv.org/abs/2309.05519) | LLM、跨模态适配器和图像/视频/音频扩散解码器连接 | 是 any-to-any 系统的重要起点；主要复用已有专家，不能当作单一共享生成主干的证据 | 摘要 |
| [DreamLLM，2023](https://arxiv.org/abs/2309.11499) | 联合学习语言与图像生成，支持自由交错文档 | 将“理解—生成协同”和交错内容生成放到同一研究问题中；具体协同仍需数据与计算控制 | 正文：框架与任务 |
| [SEED-LLaMA，2023](https://arxiv.org/abs/2310.01218) | 用 SEED tokenizer 做大规模交错预训练与指令调优 | 展示多轮上下文图文生成；与早期 SEED tokenizer 工作有关，但不是同一训练规模 | 摘要 |
| [Emu2，2023](https://arxiv.org/abs/2312.13286) | 将交错自回归模型扩到 37B，研究多模态 in-context learning | 支持视觉提示、主体条件生成等；扩规模效果不能只归因于统一架构 | 摘要 |
| [MM-Interleaved，2024](https://arxiv.org/abs/2401.10208) | 固定数量视觉 token 容易丢失多图细节；用多尺度、多图特征同步器访问历史图像 | 改善细节感知与条件图像一致性；提示“只经语义瓶颈传信息”可能不足 | 正文：问题与模块 |
| [VILA-U，2024](https://arxiv.org/abs/2409.04429) | 统一视觉塔对齐离散 token 与语言，统一 next-token prediction | 展示无需独立扩散生成器的图像/视频理解与生成；效果依赖视觉表示和训练数据质量 | 正文：框架 |
| [JanusFlow，2024](https://arxiv.org/abs/2411.07975) | 在 LLM 内结合 AR 与 rectified flow，并解耦、对齐两类视觉编码器 | 说明 Janus 的接口设计可以与连续生成结合；不能把整个 Janus 家族都归入离散 AR | 摘要 |
| [Orthus，2024](https://arxiv.org/abs/2412.00127) | AR 主干配离散语言头与连续视觉 diffusion head | 获得交错图文生成；“AR 模型”仍可能在视觉输出头内使用扩散 | 摘要 |
| [Liquid，2024](https://arxiv.org/abs/2412.04332) | 共享图文离散序列，不使用外部 CLIP 输入 embedding；研究规模与联合训练损失 | 报告任务干扰随规模减弱；是特定规模区间的经验结果，不是一般性定理 | 摘要 |
| [ILLUME，2024](https://arxiv.org/abs/2412.06673) | 语义视觉 tokenizer、分阶段训练、自评图文一致性 | 强调数据效率和自增强对齐；自评是否可靠是后续自训练研究的共同问题 | 摘要 |
| [MetaMorph，2024](https://arxiv.org/abs/2412.14164) | Visual-Predictive Instruction Tuning，同时预测离散文本与连续视觉 token | 报告理解数据可有效帮助生成；需要区分数据内容带来的知识和任务形式带来的收益 | 摘要 |
| [UGen，2025](https://arxiv.org/abs/2503.21193) | 渐进激活视觉词表，缓解一次引入大词表的优化困难 | 报告相对普通统一 AR 配方的综合改善；提示训练课程也是变量 | 摘要 |
| [Harmon，2025](https://arxiv.org/abs/2503.21979) | 复用 masked autoregressive 视觉编码器，将生成中学到的表示用于理解 | 是“从生成表示走向理解”的路线；并非所有生成目标都会产生同样的语义特征 | 摘要 |
| [X-Omni，2025](https://arxiv.org/abs/2507.22058) | 语义视觉 tokenizer、离散 AR 主干、离线扩散像素解码器，结合 RL | 改善生成质量和文字渲染；主干是 AR 不等于整条像素生成链没有扩散 | 摘要 |

## 2. 表示与 tokenizer：信息容量、语义和细节如何共同保留

| 文献 | 研究问题与方法 | 得到什么、怎样理解 | 证据 |
|---|---|---|---|
| [TokenFlow，2024](https://arxiv.org/abs/2412.03069) | 语义和像素双码本，通过共享索引对齐 | 既可取高层语义又可重建细节；不是把同一向量同时强迫为两种极端表示 | 正文：双码本 |
| [QLIP，2025](https://arxiv.org/abs/2502.05178) | 二值球面量化；动态平衡重建与图文对齐；两阶段处理 batch/显存要求 | 报告重建与零样本识别可兼容；“目标天然冲突”并非唯一解释 | 正文：训练设计 |
| [DualToken，2025](https://arxiv.org/abs/2503.14324) | 分离高层语义和低层细节的视觉词表 | 报告 ImageNet rFID 0.25、零样本准确率 82.0%；两项指标不同，不能相加为统一能力分数 | 摘要 |
| [UniToken，2025](https://arxiv.org/abs/2504.04423) | 结合连续与离散视觉输入，使任务选择所需信息 | 属于混合接口；不要与 UniTok 混淆 | 摘要 |
| [Selftok，2025](https://arxiv.org/abs/2505.07538) | 从反向扩散过程构造带因果先验的离散视觉 token | 探索适合 AR 与 RL 的视觉序列；其 Bellman 论证依赖特定构造，不能扩成空间 token 无法做 RL | 摘要 |
| [UniCode²，2025](https://arxiv.org/abs/2506.20214) | 大规模 SigLIP 聚类码本；冻结锚点码本和可学习细化码本级联 | 研究扩大词表时的利用率与稳定性；码本容量不能单靠条目数量衡量 | 摘要 |
| [TUNA，2025](https://arxiv.org/abs/2512.02014) | VAE 与表示编码器级联，建立统一连续视觉空间 | 报告理解、图像/视频生成及编辑收益；仍继承外部预训练模块 | 摘要 |
| [UniWeTok，2026](https://arxiv.org/abs/2602.14178) | 大型隐式二值码本、前后蒸馏、生成感知先验 | 展示大容量离散表示；2^128 是组合空间，不是显式存放 2^128 个 embedding | 摘要 |
| [EvoTok，2026](https://arxiv.org/abs/2603.12108) | 残差量化轨迹从像素信息逐步演化到语义，比较监督施加深度 | 13M 图像训练，256 分辨率 rFID 0.43；GenEval 0.75；轨迹方向和监督层次是关键 | 正文：表 3、深度消融 |
| [HYDRA，2026](https://arxiv.org/abs/2603.15228) | Gen-ViT→低维 Generation-Semantic Bottleneck→Sem-ViT | 报告 rFID 0.08、GenEval 0.86；分阶段消融支持训练配方作用，不能仅凭主表断言普遍协同 | 正文：架构、表 4 |
| [UniCom，2026](https://arxiv.org/abs/2603.10702) | 压缩连续语义表示，比较通道压缩与空间降采样 | 报告通道压缩更适合所测重建/生成，Transfusion 式交互优于其 query 基线 | 正文：表示与对比 |
| [Tuna-2，2026](https://arxiv.org/abs/2604.24763) | 去掉 VAE 和语义编码器，像素 patch 输入、clean-image prediction 与 flow loss | 大规模训练下理解优于编码器变体；编码器变体早期收敛及部分生成更好，不能写成无条件胜出 | 正文：架构、实验分析 |
| [Representation Forcing，2026](https://arxiv.org/abs/2605.31604) | 先预测理解编码器的离散语义表示，再以其为上下文生成像素 | 受控像素消融 GenEval 0.25→0.76；理解 6/8 项改善，但不全面超过 VLM-only | 正文：表 2—3 |
| [HYDRA-X，2026](https://arxiv.org/abs/2606.13289) | 同一 ViT 统一图像/视频表示；分层时间压缩、教师语义监督、latent 级编辑交互 | 将 tokenizer 问题扩到时空与编辑保持；因果时间注意力、压缩次序都有消融 | 摘要 |
| [PixelUMM，2026](https://arxiv.org/abs/2609.38597) | 图像 patch、视频 tubelet，线性像素接口与 MoT，AR 文本＋像素 flow | 将 encoder-free 路线扩到视频；仍要考虑时空 token 数与训练成本 | 正文：方法 |

## 3. 生成目标：AR、离散扩散、连续流并没有收敛到唯一答案

| 文献 | 研究问题与方法 | 得到什么、怎样理解 | 证据 |
|---|---|---|---|
| [UniDisc，2025](https://arxiv.org/abs/2503.20853) | 图文统一 masked discrete diffusion，研究规模和采样预算 | 联合补全、引导和并行生成具有自然接口；速度应连同采样步数与质量报告 | 正文：问题与目标 |
| [FUDOKI，2025](https://arxiv.org/abs/2505.20147) | 离散 flow matching 与 kinetic-optimal velocities，继承 AR 模型初始化 | 超出单纯 mask 恢复的转移过程；试验支持双向上下文与迭代细化的可行性 | 摘要 |
| [Muddit，2025](https://arxiv.org/abs/2505.23606) | 从预训练文生图模型继承视觉先验，加轻量文本解码能力 | 统一扩散也可从生成器出发；与从语言模型出发的模型继承知识不同 | 摘要 |
| [Lavida-O，2025](https://arxiv.org/abs/2509.19244) | Elastic-MoT 连接大小不同的理解/生成分支，配 token 压缩和分层采样 | 支持 grounding、编辑、1024px 生成；全扩散并不意味着所有分支等大或所有参数相同 | 摘要 |
| [Lumina-DiMOO，2025](https://arxiv.org/abs/2510.06308) | 统一离散扩散，分阶段训练，多任务与 maximum-logit cache | 缓存加速同时增显存；图像采样速度收益明显大于分块文本生成，不能只报最高倍率 | 正文：第 7 节 |
| [Omni-Diffusion，2026](https://arxiv.org/abs/2603.06577) | 文本、图像、语音统一遮蔽离散扩散 | 探索多于两模态的统一联合分布；模态支持应逐项核实 | 摘要 |
| [LLaDA2.0-Uni，2026](https://arxiv.org/abs/2604.20796) | SigLIP-VQ、MoE 离散扩散主干、扩散图像解码器，prefix 优化与蒸馏 | 主干图文统一去噪，但像素解码仍有独立机制；训练表为 100B＋210B＋80B token | 正文：训练表、生成比较 |
| [FullFlow，2026](https://arxiv.org/abs/2605.20316) | 在预训练 flow 文生图模型上学习 LoRA、文本插入过程与轻量文本头 | 同预算 SD3 实验改善 FID/CIDEr；FID 参考是冻结 SD3 输出，caption 参考为 Moondream 标注，不能直接与 COCO 标准 FID/CIDEr 排名比较 | 正文：表 2、4 与局限 |
| [Multimodal Flow，2026](https://arxiv.org/abs/2609.40362) | 图像和文本 embedding 均连续化，按 chunk-causal hyperchunk 学同一向量场 | 1.6B、150B token 设置报告 GenEval 0.82；提示全连续路线也应纳入比较 | 正文：方法与表 1—3 |

| [Rosetta，2026](https://arxiv.org/abs/2607.00293) | 共享基础专家与可插拔模态专家，动量锚定正交投影 | 研究增加模态时的遗忘；应与同预算回放、冻结和普通梯度方法比较 | 摘要 |

## 5. 后训练：对齐、强化学习与自改进

| 文献 | 研究问题与方法 | 得到什么、怎样理解 | 证据 |
|---|---|---|---|
| [HermesFlow，2025](https://arxiv.org/abs/2502.12148) | 同源理解/生成偏好对，Pair-DPO 和 self-play | 论文内 Show-o 基线 GenEval 0.53→0.69；不能拿另一版本 Show-o 的 0.68 当同一对照 | 正文：表 2—3、训练设置 |
| [MindOmni，2025](https://arxiv.org/abs/2505.13031) | 统一 VLM＋生成模块，CoT SFT，再用 RGPO 反馈优化 | 将推理策略与生成结果相联系；需分辨推理数据与 RL 各自贡献 | 摘要 |
| [CoRL / ULM-R1，2025](https://arxiv.org/abs/2505.17534) | 先联合 RL，再任务细化；循环一致性与图文匹配奖励 | 基线 GenEval 0.73→0.77、MMMU 36.3→42.3；消融中联合路线优于仅生成 RL，但收益依任务而异 | 正文：表 1—3、消融 |
| [PairUni，2025](https://arxiv.org/abs/2510.25682) | 合成/检索得到语义配对数据，PairGRPO 相似度加权 advantage | 7B MMMU 41.1→47.0；数据配对贡献明确，去掉相似度加权时 GenEval 不变，不应把所有增益归于新优化式 | 正文：表 1、5—6 |
| [UniCorn，2026](https://arxiv.org/abs/2601.03193) | 同模型担任 proposer、solver、judge，自生成监督和循环一致性 | 报告多项生成提升并保持理解；闭环自洽不能代替独立正确性 | 摘要 |

## 使用这份矩阵时的注意点
