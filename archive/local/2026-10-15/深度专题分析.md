# UMM 深度专题分析：从模型设计到协同证据

调研截止：2026-10-15。本文接续[研究综述](UMM研究综述.md)，重点分析论文之间的关系、受控实验与尚不能成立的推论。完整问题—方法—结果记录见[核心矩阵](文献矩阵.md)与[扩展矩阵](扩展文献矩阵.md)。

## 1. 应当用什么研究命题理解 UMM

将图像记为 $I$、文本为 $T$、其他上下文为 $C$，理解涉及 $p(T\mid I,C)$，生成涉及 $p(I\mid T,C)$，编辑涉及 $p(I'\mid I,T,C)$。交错任务则在一个持续增长的历史上交替生成文本和视觉状态。

这些条件分布能够由同一个联合模型导出，但实际神经网络使用什么表示、哪些条件分布获得训练、优化是否充分，是另外的问题。因此“同一概率框架”“同一参数文件”“两项任务都能做”“两项能力相互促进”是不同命题。这一层区分可以解释许多看似矛盾的研究结果。

| 研究命题 | 典型证据 | 尚不能推出什么 |
|---|---|---|
| 能力共存 | 同一检查点完成理解和生成 | 两种能力互相帮助 |
| 联合训练有益 | 加入另一任务后，目标任务改善 | 收益一定来自任务形式而非额外数据 |
| 单方向知识迁移 | 只教理解，生成也获得同一新知识 | 在所有任务和模型上双向对称 |
| 推理时视觉辅助 | 先画中间图后回答更好 | 比等预算文字推理或工具执行更高效 |
| 跨模态一致 | 文字答案与图像表达一致 | 两者一定正确 |
| 闭环稳定 | 长期交错生成仍保留事实、实体与状态 | 具有通用世界模型或可靠行动能力 |

UniMRG、Transferability、Entry Point、UniG2U、XTC、LongMIG 分别为这些命题提供不同实验，不能用一个总分替代全部问题。[UniMRG](https://arxiv.org/abs/2601.21406)、[Transferability](https://arxiv.org/abs/2607.04423)、[Entry Point](https://arxiv.org/abs/2608.17564)、[UniG2U](https://arxiv.org/abs/2603.03241)、[XTC](https://arxiv.org/abs/2604.25072)、[LongMIG](https://arxiv.org/abs/2610.17080)

我的综合判断是：**UMM 的科学价值需要通过“能力之间增加了什么可用联系”来证明；其工程价值还可以来自部署整合、上下文复用和成本降低。两种价值都成立，但证据不同。**

## 2. 表示冲突：不是一句“理解要语义、生成要细节”就能解释完

### 2.1 三个经常被混成一个的问题

第一是**信息损失**。识别一只猫可能不需要准确保留毛发纹理，重建同一张猫图却需要。若语义编码器丢掉信息，后端再强也只能生成合理细节，未必恢复原图细节。

第二是**建模难度**。完整保留信息不意味着该表示容易生成。高维连续语义特征、巨大离散码本、长视觉序列，都可能增加分布学习难度。

第三是**优化兼容性**。同样的信息容量下，损失尺度、初始化、训练顺序和监督施加层次会改变最终结果。VILA-U 从头同时训练对齐与重建时表现较差，使用 CLIP 初始化再联合训练可以改善；QLIP 则通过动态损失平衡与分阶段训练协调目标。[VILA-U，§3.1](https://arxiv.org/abs/2409.04429)、[QLIP](https://arxiv.org/abs/2502.05178)

因此，看到“联合目标比单目标差”，至少要区分：表示容量不足、表示格式不合适、训练没有收敛、损失失衡，以及确实存在任务不兼容。

### 2.2 各类方法到底改了什么

| 处理方式 | 代表工作 | 实际改变的变量 | 需要额外检查 |
|---|---|---|---|
| 分开视觉编码 | Janus、BAGEL | 分别保留语义和生成所需信息 | 主干中如何建立联系、视觉上下文是否翻倍 |
| 扩大离散容量 | UniTok、UniCode²、UniWeTok | 码本容量、组合方式与利用率 | 可用容量、序列长度、优化稳定性 |
| 双码本/词表 | TokenFlow、DualToken | 细节和语义分别编码，再建立映射 | 映射是否对新概念仍有效 |
| 同编码器、不同接口 | MANZANO | 理解取连续特征，生成预测离散语义 | 接口和下游解码器成本 |
| 分层演化 | EvoTok、HYDRA | 不同深度承担重建与语义监督 | 监督顺序是否有受控消融 |
| 压缩连续语义 | UniCom、BLIP3-o | 在语义空间学习生成分布 | 压通道还是空间、decoder 能恢复什么 |
| 直接像素建模 | Tuna-2、SenseNova-U1/U1.5、PixelUMM | 移除外部 latent bottleneck | 高维输出、数据效率与时空分辨率 |

来源：[TokenFlow](https://arxiv.org/abs/2412.03069)、[DualToken](https://arxiv.org/abs/2503.14324)、[UniCode²](https://arxiv.org/abs/2506.20214)、[UniWeTok](https://arxiv.org/abs/2602.14178)、[EvoTok](https://arxiv.org/abs/2603.12108)、[HYDRA](https://arxiv.org/abs/2603.15228)、[UniCom](https://arxiv.org/abs/2603.10702)、[BLIP3-o](https://arxiv.org/abs/2505.09568)，其余见主综述。

这些路线不构成单线替代关系。比如 UniTok 强调量化容量，TokenFlow 强调双类特征的对应，EvoTok 强调监督层次；三者可以同时有效，因为它们处理的瓶颈不同。

### 2.3 哪些实验更有解释力

MANZANO 的价值在于同规模接口消融：纯离散与混合接口的生成指标相近，而 text-rich 理解明显不同。EvoTok 比较像素与语义监督施加的深度，研究“沿哪个方向演化”；UniCom 比较同一压缩空间上的 query 与 Transfusion 式交互，减少了表示不同造成的混淆。[MANZANO](https://arxiv.org/abs/2509.16197)、[EvoTok](https://arxiv.org/abs/2603.12108)、[UniCom](https://arxiv.org/abs/2603.10702)

读 tokenizer 论文至少要同时看三类结果：重建、理解、生成。只报告很低的 rFID，不能证明 token 包含可用语义；只报告高 ImageNet 准确率，不能证明可以恢复文字和几何细节；只报告 GenEval，也不能说明参考图像身份是否保真。

## 3. 生成范式：需要按三条轴分类

“AR 还是 diffusion”过于粗糙。应分别记录：**主干怎样预测、视觉表示是什么、像素最后怎样产生。**

| 模型/家族 | 主干中的主要预测方式 | 视觉建模对象 | 像素输出路径 |
|---|---|---|---|
| Chameleon、Emu3 | 图文离散 AR | 离散视觉索引 | 视觉 tokenizer 的解码器 |
| Transfusion、BAGEL | 文本 AR＋视觉扩散/flow | 连续视觉 latent | VAE 解码 |
| Show-o | 文本 AR＋视觉离散去噪 | 离散视觉 token | 视觉解码器 |
| MANZANO、X-Omni | 语义层 AR | 离散语义 token | 扩散像素解码器 |
| MMaDA、Lumina-DiMOO | 图文离散扩散 | 文本和图像 token | 视觉解码器 |
| LLaDA2.0-Uni | 分块离散扩散 | 语义离散 token | 扩散图像解码器 |
| FullFlow | 文本插入过程＋图像 flow | 文本符号与连续 latent | 原有生成器的图像解码路径 |
| Multimodal Flow | 连续 chunk flow | 文本与视觉 embedding | 各自输出映射/解码 |
| Tuna-2、PixelUMM | 文本 AR＋像素 flow | 像素 patch/tubelet | 从主干直接预测像素 |

来源：[X-Omni](https://arxiv.org/abs/2507.22058)、[LLaDA2.0-Uni](https://arxiv.org/abs/2604.20796)、[FullFlow](https://arxiv.org/abs/2605.20316)、[Multimodal Flow](https://arxiv.org/abs/2609.40362)、[PixelUMM](https://arxiv.org/abs/2609.38597)，其余见主综述。

两个具体的分类陷阱：

- HunyuanImage 3.0 摘要将系统描述为 AR 框架，但正文明确在 VAE 特征上整合 diffusion，与 Transfusion/JanusFlow 类似。它不应被当作“纯离散 AR 生图”的代表。[正文](https://arxiv.org/abs/2509.23951)
- Lance 摘要使用从头训练的表述，方法部分却明确继承 Qwen2.5-VL，并使用 Wan2.2 VAE。这里不能推导出模型所有组件均随机初始化。判断“原生”时必须读初始化和训练阶段。[正文](https://arxiv.org/abs/2605.18678)

### 3.1 全扩散的统一在哪里

对遮蔽位置集合 $M$，一个简化的离散去噪目标可写为：

\[
\mathcal L_{mask}=\mathbb E_{x,t,M(t)}\left[-w(t)\sum_{i\in M(t)}\log p_\theta(x_i\mid x_{\bar M},t)\right].
\]

文本和视觉可以共享这种恢复目标；但 mask 分布、采样日程、分块方式不必相同。MMaDA 已明确区分语言和视觉的采样策略；Lumina-DiMOO 的图像生成全局并行，而文本使用分块生成。因此“统一扩散”不代表解码操作完全一致。[MMaDA](https://arxiv.org/abs/2505.15809)、[Lumina-DiMOO](https://arxiv.org/abs/2510.06308)

UniDisc 提供联合补全和质量—采样预算权衡；FUDOKI 用离散 flow 超出单纯遮蔽恢复；LLaDA2.0-Uni 则结合语义离散表示、MoE 和像素扩散解码。全扩散路线本身也在分化。[UniDisc](https://arxiv.org/abs/2503.20853)、[FUDOKI](https://arxiv.org/abs/2505.20147)、[LLaDA2.0-Uni](https://arxiv.org/abs/2604.20796)

### 3.2 为什么不能只比较推理步数

AR 的每步与扩散的每步计算量不同；是否有 KV cache、每步更新多少 token、是否有 CFG 双分支、视觉解码器多贵，都会影响实际速度。Lumina-DiMOO 的 ML-Cache 在其设置下带来约 2 倍加速，同时将 1024px 生图显存从 38.9GB 增至 45.9GB；理解侧的加速小于生成侧。应报告同质量下延迟/显存，而非单独宣称并行步数更少。[Lumina-DiMOO，§7.1](https://arxiv.org/abs/2510.06308)

## 4. 原生像素路线：删除 VAE 后，困难转移到了哪里

直接像素建模减少外部压缩空间的限制，也让输入、输出更接近原始信号。但是像素空间维度高，模型必须同时学习结构和局部细节。是否需要外部编码器，与是否需要有效语义引导，是两回事。

### 4.1 Representation Forcing 是一个有解释力的例子

该方法保留可联合训练的理解编码器；其 EMA 副本产生目标特征，经在线量化成为表示 token。主干先用 AR 预测这些 token，再利用它们进行像素 flow 生成。训练时能看到目标表示，推理时必须自行预测；它去掉了外部 VAE，但不是完全没有理解编码器。[方法](https://arxiv.org/abs/2605.31604v4)

论文的 256px 消融如下，不能与更高分辨率主结果混为一组：

| 设置 | 像素生成 GenEval | VAE 生成 GenEval |
|---|---:|---:|
| 无 Representation Forcing | 0.25 | 0.52 |
| 有 Representation Forcing | 0.76 | 0.77 |

同一像素设置中，REPA 式辅助对齐为 0.43，显式表示预测为 0.76。这个对照支持：**在这些条件下，把语义表示变成生成过程必须产出的中间变量，比只施加辅助对齐损失更有效。**它没有证明所有模型都必须采用这种方式。[表 3](https://arxiv.org/abs/2605.31604v4)

理解端也需保留基准参照。Pixel+RF 的 MMMU 为 54.2，优于 Pixel 的 49.9，但 VLM-only 为 56.2；BLINK 为 53.0，也低于 VLM-only 的 56.2。故可说 RF 缓解了部分统一训练退化，不能说已经全面证明生成任务提高了原始理解能力。[表 2](https://arxiv.org/abs/2605.31604v4)

### 4.2 与 Tuna-2、SenseNova、PixelUMM 的关系

Tuna-2 直接使用像素 patch，并引入 masking 训练；其无编码器变体在大规模训练后理解更强，但编码器变体在早期收敛、部分生成表现上仍有优势。SenseNova-U1/U1.5 进一步研究像素接口、专家和高分辨率训练。PixelUMM 把问题扩到视频 tubelet，消融表明 patch 大小改变了序列长度、每步图像数量与学习难度，不能只按吞吐选择。[Tuna-2](https://arxiv.org/abs/2604.24763)、[SenseNova-U1](https://arxiv.org/abs/2605.12500)、[U1.5](https://arxiv.org/abs/2609.11929)、[PixelUMM](https://arxiv.org/abs/2609.38597)

由这些证据得到的研究问题是：**语义先验应来自外部编码器、内部中间表示，还是足够大的像素联合训练？在什么数据与计算条件下，各自更有效？**目前不能宣布某种方式全面取代其余方式。

## 5. 知识迁移：新概念实验比两个排行榜总分更直接

### 5.1 为什么熟悉概念上的双高分还不够

一个模型会回答“香蕉通常是什么颜色”，也会画黄色香蕉，可能只是两条路径分别学过相同事实。要测试迁移，最好让新知识只进入一个方向，再测另一个方向，并避免另一任务的数据泄漏。

Transferability 用单方向计数微调，已经比联合总分更接近这一目标。Entry Point 进一步用渲染的 3D 实体与新伪词绑定知识，并筛除基础模型已有稳定行为的名字。[Transferability](https://arxiv.org/abs/2607.04423)、[Entry Point](https://arxiv.org/abs/2608.17564)

### 5.2 Entry Point 的关键结果及边界

其 56 个概念实验发现两个方向都有迁移。但迁移率方向差的置信区间跨零，因此**不能说已经证明理解→生成的迁移率显著更高**。确定性更强的差异在能力类型：生成侧学会新名字后，理解侧可能能从候选项中匹配名字，却不能在没有候选时主动说出名字。

例如生成注入使四选一匹配从 0.254 到 0.600，但无候选名字生成仍接近基础水平。这说明多选题可能测到匹配能力，而不是完整的概念命名能力。论文的冻结激活干预和不同层注入进一步显示，新概念进入共享计算的位置会影响另一任务能否使用它。[表 1—2、层间干预](https://arxiv.org/abs/2608.17564)

这些结果支持“共享语义入口很重要”，但四种模型之间的差异仍混合了预训练与架构因素。层间干预能支持具体模型中的因果解释，不能自动把跨模型观察也提升为因果结论。

### 5.3 与其他诊断怎样拼起来

Cross-Branch Steering 把一个分支的语义方向施加到另一分支，观察到理解到生成更有效的方向性。UniKE 则发现文字知识修改成功不保证图像生成同步改变。两者从激活干预、参数编辑角度补充新概念实验。[Cross-Branch Steering](https://arxiv.org/abs/2607.26411)、[UniKE](https://arxiv.org/abs/2606.00477)

由此更合适的研究对象是：知识以何种格式、在哪些层和接口中可被另一个任务读取，而不是仅统计共享参数百分比。

## 6. 梯度冲突：需要区分优化现象与可预测的机制

设理解和生成在共享参数上的梯度为 $g_U,g_G$。常见方向指标为：

\[
c=\frac{g_U^\top g_G}{\|g_U\|\|g_G\|}.
\]

负值意味着两个小步更新在局部一阶近似下方向不一致，但它并不直接等于最终泛化性能下降。梯度大小、曲率、训练阶段、batch 抽样和任务难度都可能改变关系。因此“负余弦减少”和“理解—生成权衡改善”必须分别测量。

### 6.1 一个反例：冲突指标下降，最终权衡未改善

Gradient Conflict Audit 在 5×5 彩色网格世界建立共享 Transformer，同时做生成和问答。它比较 63 个配置、372 个测量 checkpoint，并对冲突抑制强度做干预。常用方向指标没有可靠预测最终权衡；增加冲突抑制强度也未带来相应改善。[实验与讨论](https://arxiv.org/abs/2609.38465)

该实验的优点是目标可精确验证、能重复比较。边界也明确：这是受控小世界，大部分正常配置较早掌握生成，剩余差异较多落在理解轴上。它说明诊断指标需要验证，不说明生产级 UMM 上所有梯度方法都无效。

### 6.2 一个正例：定位到 token 位置后干预有效

Position-Aware Modulation 研究 Show-o 和 Janus-Pro，发现相同层内，不同视觉 token 位置的干扰明显不同。它针对高冲突位置移除与理解梯度反向的分量，保持网络结构和可训练参数预算；Show-o 上相较层级分离方法，报告 MME +21、GenEval +2.4 点，随机位置控制只恢复部分收益。[方法和对照](https://arxiv.org/abs/2609.38485)

与前一篇并不矛盾：一篇检验粗粒度指标能否预测最终表现，一篇提出位置相关干预并直接测任务表现。后者的成功仍不等于全局负余弦是普适代理指标。

Pareto LoRA 与 FullFlow 还表明，梯度**量级**失衡可以与方向问题分开存在。FullFlow 在 SD3 适配中观察到文本梯度约大 25 倍，并使用 EMA 调权；作者明确说明该比例依赖骨干。[Pareto LoRA](https://arxiv.org/abs/2606.17296)、[FullFlow](https://arxiv.org/abs/2605.20316)

**撤回记录。**检索到的《Do Understanding and Generation Fight?》已于 2026-05-22 撤回，作者注明实验不足以支持其跨架构论断。这里保留记录，不将其负面 DPO 结果纳入证据链。[撤回页面](https://arxiv.org/abs/2603.17044v2)

## 7. 后训练：真正变化的是奖励、配对结构，还是新增知识

### 7.1 三条有代表性的路径

| 工作 | 优化单位 | 它试图建立的联系 |
|---|---|---|
| HermesFlow | 同源理解/生成偏好对，Pair-DPO，自博弈 | 同一个语义事件的“能判断”与“能生成”保持一致 |
| CoRL | 联合 GRPO 后任务细化，循环和匹配奖励 | 两任务共享策略改善，再强化各自不足 |
| PairUni | 语义匹配的理解—生成样本对，PairGRPO | 让共同训练的数据真正在内容上对应 |

来源：[HermesFlow](https://arxiv.org/abs/2502.12148)、[CoRL](https://arxiv.org/abs/2505.17534)、[PairUni](https://arxiv.org/abs/2510.25682)

HermesFlow 在其论文所用 Show-o 基线上将 GenEval 从 0.53 提至 0.69；不同时间的 Show-o 版本分数不同，不能替换基线。CoRL 的 Janus-Pro 小模型从 GenEval 0.73 到 0.77、MMMU 36.3 到 42.3；联合 RL 与单任务 RL 的比较比摘要中的平均百分比更有解释力。

### 7.2 PairUni 的消融揭示了什么

在其小模型消融中，未配对数据的 GenEval 为 0.71，随机配对为 0.73，最终 PairUG-16k 为 0.79。MMMU 对应 38.4、38.4、40.4。结果支持语义配对数据有益。

但 PairGRPO 的相似度加权消融中，去掉该项，1B 与 7B 的 GenEval 均保持不变；部分理解指标提高。故更准确的解释是：**整体配对训练有效，附加加权主要在所测理解指标上带来增益。**不能把整体生成提升全归于奖励加权公式。[表 5—6](https://arxiv.org/abs/2510.25682)

### 7.3 自改进能否突破自我判断的盲点

UniCorn、GvU、MATE 用同一模型不同角色产生监督，优点是减少外部人工数据；问题是模型可能在理解和生成上共享盲点。闭环一致可以作为约束，但不能充当唯一真值。[UniCorn](https://arxiv.org/abs/2601.03193)、[GvU](https://arxiv.org/abs/2603.06043)、[MATE](https://arxiv.org/abs/2609.36224)

2026 年 10 月的 RSI 图表研究加入程序执行验证：四轮后测试从 45.7% 到 60.2%，继续训练对照为 46.3%；作者分析指出，可验证的数据构造承担主要收益，针对失败样本提供额外增益。它提供的是图表领域证据，不是无外部真值情况下的无限自我提升。[RSI](https://arxiv.org/abs/2610.03002)

值得深入研究的是：哪些任务能够廉价获得独立真值，例如计数、几何约束、程序渲染或可执行状态变化；如何把这些监督传到更开放的生成任务。这里的“独立”针对模型自评偏差，并非要求为所有输出增加复杂检查。

## 8. 评测的新焦点：会解释、会画图，为什么仍会画错答案

### 8.1 三种诊断协议特别有价值

**拆开推理与渲染。**VGUBench 比较同题文字答案、视觉答案以及直接按明确描述渲染。若前后两项强、视觉回答弱，不能把失败简单归为画质不足。[VGUBench](https://arxiv.org/abs/2602.23711)

**拆开推理内容与上下文负担。**UReason 比较直接生成、完整推理上下文生成、仅保留推理提炼提示的生成。最后一种经常更好，说明知识可能已在文字中表达，却未被后续视觉过程可靠使用，或者多余推理上下文造成干扰。[UReason](https://arxiv.org/abs/2602.08336)

**拆开基本能力与组合能力。**RealUnify 使用端到端及分步骤评价；Uni-MMMU 在迷宫、拼图和学科任务中检查文字行动与视觉状态。这有助定位是模型本身不会推理/画图，还是能力之间无法组合。[RealUnify](https://arxiv.org/abs/2509.24897)、[Uni-MMMU](https://arxiv.org/abs/2510.13759)

### 8.2 不能把一致性奖励变成“共同犯错奖励”

建议把结果至少分成四种：文字正确且图像正确、文字正确图像错误、文字错误图像正确、两者都错误。对最后一类再区分是否表达同一个错误。这样能避免“一致性提高”掩盖正确率下降。

XTC 的匹配原子事实、GapEval 的输出模态差距、Unison 的统一/解耦评测和 UEval 的开放式 rubric，分别覆盖其中不同方面，不能替代彼此。[XTC](https://arxiv.org/abs/2604.25072)、[GapEval](https://arxiv.org/abs/2602.02140)、[Unison](https://arxiv.org/abs/2606.26984)、[UEval](https://arxiv.org/abs/2601.22155)

### 8.3 评价器也是实验条件

生成基准可能使用检测器、VQA 模型、LLM 裁判或人工评分。换裁判版本、提示模板和图像尺寸可能改变数值。以 FullFlow 为例，表中 FID/CMMD 是相对冻结 SD3 输出分布，caption 指标相对 Moondream 标注；它们适合该受控实验，不宜与采用真实图像、人工 caption 的常规排行榜直接拼表。[FullFlow，表 4](https://arxiv.org/abs/2605.20316)

## 9. 交错生成：为什么更长上下文可能更差

传统问答把历史当作证据。交错生成中，历史还包括模型刚生成的、可能有偏差的视觉状态；这些状态会反过来影响未来输出。这形成了视觉版的训练—推理分布偏移和误差累积。

MM-Interleaved 早期用多尺度历史视觉特征保留细节；ChatUMM 训练历史依赖和干扰轮鲁棒性；UniLongGen 则观察到过多视觉事件可能污染后续生成，采用选择性保留。三者处理的是历史信息不足、历史依赖不会用、历史信息过多会干扰三个不同问题。[MM-Interleaved](https://arxiv.org/abs/2401.10208)、[ChatUMM](https://arxiv.org/abs/2602.06442)、[UniLongGen](https://arxiv.org/abs/2603.07540)

LongMIG 的后续工作组合持久视觉参考、场景相关历史检索及自生成历史 rollout 适配。在同骨干比较中，其 Visual Memory 指标从 UniLongGen 对照的 2.60 到 3.77；24 图压力测试还分别消融参考保留、场景检索和 rollout。这类实验比单独展示一段长故事更有说服力，但指标仍来自该基准协议，不能当作通用记忆容量。[LongMIG，表 1—2](https://arxiv.org/abs/2610.17080)

这条路线的实际研究问题包括：哪些视觉状态必须保存，哪些信息适合变成文字/结构化状态，旧图何时应被新状态覆盖，以及模型能否发现自己已经丢失关键历史。

## 10. Any-to-any、世界模型和机器人：扩大范围后多了哪些问题

### 10.1 Any-to-any 不只是增加更多输出头

这一研究线有比当前 LLM 更早的基础：Versatile Diffusion 用共享/可交换层构造多流生成；UniDiffuser 让不同模态具有独立噪声时间，从同一模型取得边缘、条件和联合分布。因此 any-to-any 的“统一”也包含条件概率建模问题，并非仅是统一聊天接口。[Versatile Diffusion](https://arxiv.org/abs/2211.08332)、[UniDiffuser](https://arxiv.org/abs/2303.06555)

若给定模态子集 $X_S$，模型需要生成缺失的 $X_{\bar S}$，还可能同时无条件生成多种模态。单独生成的每一模态质量高，不保证它们描述同一事件。

OmniFlow 用多模态 rectified flow 和不同模态时间变量表示这些条件路径。MUNI 则研究共享随机 latent：它既要承载已观测模态的信息，又要让缺失模态可预测，还要使无条件联合采样保持一致。[OmniFlow](https://arxiv.org/abs/2412.01169)、[MUNI](https://arxiv.org/abs/2606.16408)

MUNI 在 PolyMNIST-Quadrant-Labels 上同时报告单条件、双条件和无条件一致性，避免只看“标签给得足够完整时能否画对”。其理论条件依赖可实现性和模型假设，不能直接变成大型语言模型的普遍保证。

### 10.2 视频与动作需要额外的状态约束

Show-o2、Lance、PixelUMM、HYDRA-X 研究时空表示与图像/视频任务统一；BagelVLA、WorldBagel 把视觉预测和动作生成带入执行过程；Puffin-World 显式建模几何、物理和相机状态。[Lance](https://arxiv.org/abs/2605.18678)、[HYDRA-X](https://arxiv.org/abs/2606.13289)、[BagelVLA](https://arxiv.org/abs/2602.09849)、[WorldBagel](https://arxiv.org/abs/2607.03461)、[Puffin-World](https://arxiv.org/abs/2609.04196)

这些研究与 UMM 主线相连，但验证目标更强：跨帧身份、遮挡后的状态、动作条件预测、闭环任务成功率和延迟。高质量视频展示只能覆盖其中一部分。

## 11. 当前哪些结论较稳，哪些还没有解决

| 结论 | 目前证据支持程度 | 不能省略的条件 |
|---|---|---|
| 单一系统同时理解与生成已可行 | 多条路线反复实现 | 实际检查点、开放接口和任务范围 |
| 完全共享不是唯一合理架构 | Janus、BAGEL、UniFork 等支持 | 总容量、激活计算、数据和共享位置 |
| 语义与细节存在实际兼容难题 | tokenizer、接口及训练消融一致指出 | 不等于理论上不可兼容 |
| 某些生成监督能帮助理解 | UniMRG、Synergy 等有条件正证据 | 数据内容、辅助目标和任务种类 |
| 单方向能力能够跨任务迁移 | 计数和新概念实验支持 | 模型差异、方向、识别与自由生成的区别 |
| 测试时先生成图一定更好 | 不成立 | UniG2U、VGAU 提供反例与条件收益 |
| 梯度冲突减少就代表最终更好 | 尚无普遍支持 | 需要直接测泛化权衡，不能只看代理量 |
| 一种架构/生成范式已全面胜出 | 不成立 | 缺少统一数据、规模、预算和任务的大范围比较 |
| 图文统一自然带来世界模型 | 证据不足 | 需要状态、干预、行动与长时闭环验证 |

表中的判断是跨论文综合分析，不是统计元分析。当前数据和评测异质性较大，不宜将跨论文分数合并计算“某路线平均领先多少”。

## 12. 研究切入点：从能明确证伪的问题开始

以下是根据现有证据提出的研究问题，不是已经完成的新实验，也不宣称无人研究。

| 问题 | 已有工作留下的具体缺口 | 能检验它的最小实验 | 有意义的结果形式 |
|---|---|---|---|
| 什么表示能跨任务传新知识？ | 计数与伪词实体有结果，关系、操作和抽象规则证据较少 | 固定骨干、只从一方向教新关系；另一方向同时测选择和自由输出 | 迁移率、方向差、保留旧能力，附数据无泄漏说明 |
| 改善了理解，还是仅减轻退化？ | 许多新 UMM 只对比旧 UMM | 保留 VLM-only；相同新增数据分别作问答、生成和多表示监督 | 两任务相对各自基线的 Pareto 改善 |
| 哪些中间视觉状态值得生成？ | 自然图未必有益，结构监督有条件收益 | 等预算文本、自然图、结构图、oracle 图；按难度分层 | 生成错误与读图错误的分解、成功率—成本曲线 |
| 共享目标语义能否同步知识编辑？ | STBridge 与 UniKE 显示目标表达和视觉实现脱节 | 相同知识更新，比较直接编辑与共享目标通道 | 文本/图像共同正确率、局部性、旧知识保持 |
| 梯度代理什么时候有效？ | 粗粒度冲突指标受到反例挑战 | 在真实模型固定小数据集上检验指标预测，再做针对干预 | 预测有效性和最终行为改善同时成立 |
| 长期生成应该记住什么？ | 检索、永久参考和 rollout 均有作用，组合成本未统一 | 同骨干、同历史预算，比较全历史/近期窗口/状态摘要/相关检索 | 远距离回访正确率、身份一致性、延迟与显存 |
| 自训练的真值从哪里来？ | 同模型评价易共享盲点 | 选择有程序/几何真值的任务，对比自评、外部验证和不筛选 | 未参与训练任务的实际迁移，而非仅奖励上升 |

从现有开源基座开展受控后训练、表示干预和评测，能够直接回答这些问题。是否从头训练大 UMM，应由研究问题是否必须控制预训练决定；仅为构造新的模块组合，没有必要先承担完整预训练成本。

## 13. 学习路线：按问题串起来，而不是背模型名称

1. **基础建模**：Chameleon → Transfusion → Show-o → MMaDA/UniDisc。能够解释 AR、mask diffusion、flow 和注意力掩码的差异。
2. **视觉表示**：Janus → TokenFlow/UniTok/QLIP → MANZANO → EvoTok/HYDRA/UniCom。能够说明每项工作改变了容量、接口还是监督层次。
3. **系统与数据**：DreamLLM/MM-Interleaved → BAGEL → Show-o2/Lance。理解交错数据、任务专家和训练阶段的作用。
4. **像素与连续路线**：TUNA → Tuna-2 → Representation Forcing → SenseNova-U1.5/PixelUMM；并读 Multimodal Flow，避免只看到 AR＋图像 flow。
5. **后训练**：HermesFlow → CoRL → PairUni → STBridge/UMM-Reflection。重点比较语义配对、奖励和新增数据的贡献。
6. **协同诊断**：UniMRG 与 UniG2U 对读；Transferability 与 Entry Point 对读；Gradient Conflict Audit 与 PAM 对读。
7. **评测与闭环**：RealUnify/Uni-MMMU → UReason/VGUBench/XTC/Unison → IMUG/LongMIG。区分正确性、统一性、计算收益和长期状态保持。

完成这条学习链后，判断一篇新论文的关键不再是名字、参数量或最高分，而是：它针对哪个已经观察到的失败，改变了什么，哪项对照排除了替代解释，以及其结果能否支持所声称的统一收益。
